# bozo-run

Phase 2's runner, and phase 3's check of the native libraries: TMB's code generated by `bozo-recomp`, on BozoEngine's own EE kernel, dispatcher and cycle model
([`docs/specs/kernel.md`](../../docs/specs/kernel.md)), with every library BozoEngine does not implement yet
answered from a call log ([`docs/specs/calllog.md`](../../docs/specs/calllog.md)). Every record of the log is made
again and checked in lockstep; the per-frame reference record (PS2XREF1,
[`docs/specs/harness.md`](../../docs/specs/harness.md) section 6) is written and compared with the reference
build's.

## Build

```sh
export PATH=/c/msys64/ucrt64/bin:$PATH
cmake -S . -B build -G Ninja -DBOZO_TMB_ELF=D:/TMB_Recomp/build/us_probe/SCUS_971.01 \
      -DBOZO_CALLLOGS=D:/BozoCaptures/tmb/calllog [-DBOZO_CAPTURES=D:/BozoCaptures/tmb] \
      [-DBOZO_FFMPEG_ROOT=D:/tmb_kit/kit/ffmpeg]   # libmpeg's decoder (else pkg-config; none: movies from the log)
cmake --build build
```

`bozo-calllog-tool externals` lists the logs' external addresses (every named stub and every override, from their
NAME and OVRD chunks, merged with the captures' list when `BOZO_CAPTURES` is set); `bozo-recomp` generates TMB's code
with them into `build/tmb_gen` (cached, never committed); `bozo-run` links it with the runtime (`runtime/`) and the
log-backed host (`log_host.cpp`).

### With a port's overrides (phase 4)

The run is a library (`bozo_run`, `run_main.h`: `bozo::run::main`). A port's checker links it with its own generated
code and its overrides (`bozo/port.h`, `BOZO_PORT`): TMB_Recomp's `tmb-check` (its `cmake/bozo.cmake`, `-DTMB_BOZO=ON
-DBOZO_ENGINE_DIR=<this tree>`). Its overrides then run natively instead of being answered from the log, each call
checked against its record: the context words it changed, its memory runs, its traced calls, the operations and the
frame end inside it, and whether it returned or left to the dispatcher ([`kernel.md`](../../docs/specs/kernel.md)
section 3b). Its code is generated with the externals `bozo-externals` writes from the ELF and the port's override list
(`tools/externals`); at startup every registered override must be one of them. `--overrides log` answers them from the
log as before. The summary adds `port overrides:` (calls, the out-calls made inside them, divergences) and `draws`
(the renderer's draw lists against the reference's, reported only).

```sh
build/bozo/tmb-check D:/BozoCaptures/tmb/calllog/boot.clg --ref <BozoEngine>/reference/tmb/records/boot.ref --pinned \
      --iso "D:/TMB_Recomp/Twisted Metal - Black (USA).iso"
```

## Run

```sh
build/tools/run/bozo-run D:/BozoCaptures/tmb/calllog/boot.clg --ref reference/tmb/records/boot.ref --out build/boot.ref
python tools/capture/ref_compare.py build/boot.ref reference/tmb/records/boot.ref --ignore draws,sound
```

| Option | What |
|---|---|
| `--ref <run.ref>` | compare each frame's record with the reference's (ram, scratchpad, calls, threads, eeCycle) and print the first frame each field differs at |
| `--out <out.ref>` | write BozoEngine's PS2XREF1 record (draws and sound 0: no renderer or mixer yet) |
| `--frames n` | stop after n frames (default: the log's frame limit) |
| `--elf <path>` | the game's executable (default: the one the build was generated from); its XXH64 is checked against the log's |
| `--max-errors n` | go on after a cycle divergence (the cycle is resynced to the log's) until the n-th; anything else stops the run |
| `--trace-from <record>` | print every record matched from that record index on |
| `--trace-checkpoints` | with `--trace-from`: also every checkpoint passed (where it goes on, the cycle, the charge) and every dispatcher start |
| `--pinned` | pinned mode (`kernel.md` section 4): the vblank's events at the log's points; EE time and checkpoint counts reported, not checked; eeCycle not part of the exit status |
| `--native <list>` | the native libraries answering their calls instead of the log, each call checked against its record (`docs/specs/libraries.md` section 1): `libc`, `libm`, `gs`, `pad`, `mc`, `cd`, `vu0` (the VU0 microprograms), `io` (the hardware registers), `mpeg` (libmpeg: needs a build with FFmpeg), `sif` (the SIF layer), `snd` (the 989SND sound driver behind the SIF RPC: banks are read from the disc image), comma-separated, or `all` (the default) or `none` (phase 2: everything from the log) |
| `--iso <image>` | the game's disc image for the native CD library (`libraries.md` section 8; also `BOZO_ISO`); without one the CD stays answered from the log |
| `--pad-script [player=]file` | the controllers' input for the native pads (`docs/specs/libraries.md` section 6): a reference run's frame-keyed script, for player 1 to 4 (1 when omitted; without a multitap player 2 is port 2's pad, with one players 2-4 are its slots); match1p needs `reference/tmb/scripts/ch1p_frames.txt` |
| `--card-dir <dir>` | the native memory cards' host folder (`<dir>/mc0`, `<dir>/mc1`); without it, fresh formatted cards in memory (as the reference runs' fresh user folder) |
| `--snd-log-replies on\|off\|<ids>` | pinned mode: whether the 989SND replies the reference's IOP time decided (0x11, 0x19, 0x21, 0x2c) come from 989SND's native model (`off`, the default: `libraries.md` section 15.13c), from the log (`on`), or from the log for the listed command ids only (hex, comma-separated, e.g. `11,2c`); the model is compared with the log's replies either way |
| `--overrides native\|log` | with a port linked in (`tmb-check`): its overrides run natively (the default) or are answered from the log |
| `--quiet` | only the summary |

The exit status is 0 when the whole log was made again with no divergence and every frame equals the reference: on
ram, scratchpad, calls, threads and eeCycle in free mode, and on all of them but eeCycle in pinned mode. Pinned mode
also prints how many events it placed (and which ones it took one checkpoint late), and how many records are at
another cycle or checkpoint count than BozoEngine's.

A native call that differs from its record is a divergence too (`native <function> (<library>) differs from the log:`
then the context words, the first memory byte, or the rest of the record that differ). The summary line `native
libraries:` counts the calls answered natively per library, the answered calls the native state followed (traced
`rand`, `sceMpegCreate`'s heap block, timer 0 after the frame boundary) and the divergences; then, when there are any,
the calls of a native library it had no answer for (left to the log) and the timed calls whose EE time is not the log's
(free mode). With `snd`, two `989snd:` lines: the replies the driver made and those a pinned run took from the log
because the reference's IOP time decided them (per command id, native/pinned), the commands it followed from calls
answered from the log, how often its free-mode models agree with the pinned decisions, and what it sent its
`SoundSink` (`docs/specs/libraries.md` section 15).

## Reading a log

`bozo-calllog-tool` (built always) reads what phase 3 needs from a log, streaming it:

| Command | What |
|---|---|
| `survey <log>` | per stub or override: calls, the context words they change, their memory runs, EE cycles, traced calls and records inside |
| `dump <log> <target>[,...] [n] [skip]` | the first n CALL records at those addresses: inputs, words, runs, traces, records inside |
| `calls <log> <name>[,...]` | every call to the named stubs in run order, those traced inside other calls included |
| `writes <log> <lo> <hi> [from] [to]` | the records whose memory runs touch [lo, hi) |
| `range <log> <from> <to> [bytes] [types]` | every record in [from, to), one line each (`types`: `CALL,MEM,OP`...) with its runs' first bytes |
| `io <log>` | per hardware register: loads and stores, their values, the context words and operations inside them |
| `memory <log> <record> <out> <lo> <hi>` | guest memory in [lo, hi) as the log's effects leave it at the end of a record (what out-calls and continuations wrote; guest code's own stores are not in a log) |
| `extract <log> <record> <out> <lo> <hi>` | the bytes one record's runs hold in [lo, hi), and a mask of those it covers |

## A divergence

The first record that differs stops the run:

```
DIVERGENCE 1: io-load 0x10000000: cycle 30509650227 (log 30509650235, -8); checkpoints since the last out-call: 1695 (log 1696)
  log:  #18359663 CALL f5786 c30509650235 s10127885 t1 ckp1696 pc 0x1f6a30 io-load 0x10000000 ra 0x1c98e4 ...
  here: frame 5786, cycle 30509650227, seq 10127885, thread 1 depth 0, pc 0x1f6a28, sp 0x8ff2c0, 1695 checkpoints ...
```

`log` is the record (its index in the file, frame, cycle, seq, thread, checkpoints and pc, then its fields) and `here`
BozoEngine's state. `calllog_read.py <log> list --frames A-B` and `show <index>` show the records around it; rerun
with `--trace-from <index - k> --trace-checkpoints` to see BozoEngine's checkpoints in the same stretch.
