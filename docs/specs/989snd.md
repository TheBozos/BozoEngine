# Spec: 989SND's behaviour (programs, voices, the tick, MIDI, VAG streams)

What 989SND (`/MOD/989SND.IRX` on TMB's disc, `libraries.md` section 15) does, as behaviour, for the native driver that
replaces it: data layouts, algorithms, iteration orders and integer arithmetic, written from the module's code read
with `tools/irx/irx_disasm.py` (addresses are module offsets) and checked on the analysis replay of `libraries.md`
15.13a. Not a transcription of its instructions. Three parts, each with its own open questions:

- **Part A** programs (sound types 1-3), the voice pool and its stealing, KeyOn/KeyOff, the 240 Hz tick and its
  256-tick end counter, handlers and handles, pitch and volume, the handle commands (0x15, 0x18, 0x19, 0x20, 0x21);
- **Part B** MIDI sounds (type 4): the bank's MIDI blocks, the MIDI handler, the sequencer, notes to voices;
- **Part C** VAG streams (0x2a, 0x2c-0x34): buffers, threads, the disc pipeline, the stream tick and the end rule.

Cross references inside a part ("2.1", "section 4") are to that part; Parts B and C use Part A's names.


## Part A: PlaySound, voices, the tick, and the sound-handle commands

Clean-room behavioural spec, written from the module listing (module offsets) and the module's `.data`
(read through `irx_disasm.Irx`). Addresses are module offsets. "trunc" = integer division rounding toward zero (the
code's magic-number divisions were checked to be exact truncating divisions over the full input ranges used);
"asr" = arithmetic shift right (floor). Voice index `v` is 0..47; **core = v / 24, ch = v % 24** (voices 0-23 are core 0,
24-47 core 1); a libsd voice entry is `core | ch << 1 | param`. All iteration "over voices" is v = 0..47 ascending unless
stated otherwise.

---------------------------------------------------------------------------------------------------------------------

### 1. Data structures

#### 1.1 Bank records as the driver reads them (pointers already relocated by the loader)

Bank header (`b`): `+0x00` magic (`'SBlk'` = 0x6b6c4253 goes to the SBlk code at 0x11fe0, not covered), `+0x14` s16
sound count, `+0x16` s16 program count, `+0x1c` sound table pointer, `+0x20` program table pointer.

Sound (28 bytes, `snd = b.sounds + idx*28`):

| off | type | meaning |
|---|---|---|
| 0x00 | s32 | type: 0 empty, 1-3 program sounds (3 = looping, see cmd 0x1a), 4 MIDI, 5 (0x9b10) |
| 0x04 | ptr | owning bank; 0 = not loaded/resolved (play answers 0) |
| 0x0d | s8 | program index |
| 0x0e | s8 | note |
| 0x0f | s8 | fine (1/128 semitone) |
| 0x10 | s16 | volume (0..1024 scale, 1024 = unity on the play's volume) |
| 0x12 | s8 | (type 4 only: "not looping" flag for cmd 0x1a) |
| 0x13 | s8 | volume group (index into the 8 group volumes; also selects the voice range, 2.1) |
| 0x14 | s16 | pan (degrees) |

Program (8 bytes, `prog = b.programs + p*8`): `+0` s8 tone count, `+1` s8 volume (0..127), `+2` s16 pan (degrees),
`+4` pointer to its first tone.

Tone (24 bytes): `+0` s8 priority, `+1` s8 volume (0..127), `+2` s8 centre note, `+3` s8 centre fine, `+4` s16 pan,
`+6` s8 key low, `+7` s8 key high, `+8` s8 bend-down range (semitones), `+9` s8 bend-up range, `+0x0a` u16 ADSR1,
`+0x0c` u16 ADSR2, `+0x0e` u16 flags (bit 0: reverb send), `+0x10` u32 sample start written to SSA as is (the loader
presumably makes it an absolute sound-memory address: not checked here).

#### 1.2 Voice table: 48 x 56 bytes at 0x16aa0 (`V[v]`)

| off | type | meaning |
|---|---|---|
| 0x00 | ptr | next voice in the *active voice list* |
| 0x04 | s32 | own index v (set at init) |
| 0x08 | s32 | state: 0 free; 1 linked in the active list (set at KeyOn setup, stays 1 until freed); 2 just allocated (transient, inside a play); 3 reserved (voice-reserve command 0x1700) |
| 0x0c | ptr | owner (sound handler) |
| 0x10 | fn | owner callback `cb(v, owner, reason)`; 0 = none (a program voice uses 0x7bc8) |
| 0x14 | ptr | tone |
| 0x18 | s8 | note, `0x19` s8 fine |
| 0x1a | u8 | priority (compared unsigned between voices) |
| 0x1b | s8 | volume group |
| 0x1c | u32 | age stamp (value of the tick counter `now`, 1.4) |
| 0x20 | s16 | volume L, `0x22` s16 volume R (before group scaling; may be negative = phase inverted) |
| 0x24 | s16 | pitch bend, `0x26` s16 pitch modifier |

Per-voice side arrays (BSS, zero at start, **never reset when a voice is reused**):
`lastEnvx[48]` s16 at 0x18360, `silentCount[48]` u8 at 0x183c0.

#### 1.3 Sound handler table (programs): 48 x 56 bytes at 0x197f0 (`H[i]`)

| off | type | meaning |
|---|---|---|
| 0x00 | u32 | handle word: `bit31 active | type<<24 | slot<<16 | gen`; type 0 for programs |
| 0x04 | ptr | sound; **0 = slot free** (allocation test) |
| 0x08 | ptr | effect-node chain (auto-pan etc., section 6) |
| 0x0c | s16 | copy of sound volume; `0x0e` s16 copy of sound pan |
| 0x10 | s16 | current volume (0..127 after the clamp) |
| 0x12 | s16 | current pan (degrees) |
| 0x14 | s16 | pitch modifier |
| 0x16 | u8 | flags (bit 1 = paused) |
| 0x17 | s8 | volume group (sound+0x13) |
| 0x18 | u32 | owned-voice mask, core 0 (bit ch); `0x1c` u32 core 1 |
| 0x20 | ptr | next in the *active handler list* |
| 0x24, 0x28 | ptr | parent / child links (sound chains; 0 for a program play) |
| 0x2c | s8 | note; `0x2d` s8 fine |
| 0x2e | s16 | pitch bend |
| 0x34 | u32 | zeroed at play (meaning unknown) |

Init (0x61c0): every `H[i].handle = i << 16 | 1`, sound = 0, +0x08 = 0, flags = 0. So the first play on a slot gets
generation 2.

Other pools (same handle scheme, looked up by 0x6900): type 1 (MIDI) 32 x 184 bytes at 0x1a3d0 (prefix 0x01000000,
allocator 0x65ac), type 2 8 x 44 at 0x1a270 (prefix 0x02000000, allocator 0x6688), type 4 52-byte records at `*(0x15110)`
(streams), type 5 52-byte records at 0x183f0.

#### 1.4 Globals

| addr | meaning |
|---|---|
| 0x14a40 | missed-tick count |
| 0x14a48 | lock flag (0x1630 sets, 0x16a0 clears) |
| 0x14a4c, 0x14a50 | voice-range split flag and a second word (command 0x0d, 0x161c); 0 at init |
| 0x14a54 | active voice list head |
| 0x14ab0 | `now`: tick counter, +1 per tick that runs (0x5708 reads, 0x5718 writes) |
| 0x14ab4 | suspend count (0x5430 ++, 0x544c --) |
| 0x14ab8 | tick re-entrancy guard |
| 0x14ac0 / 0x14ac4 | active handler list head / tail (link at handler +0x20, appended at the tail) |
| 0x14ad0 | s32 groupVol[8]; .data holds 127 each; module start sets groups 0, 1, 2 and 7 to 1024 (0x49ac-0x49d4), so groups 3-6 stay 127 until SetMasterVolume |
| 0x14af0 | s16 playback mode (SetPlaybackMode 0x0b; 0 at start) |
| 0x14b00 | pan table, 180 entries of (s16 L, s16 R) |
| 0x153e0[2] | reverb-send mask per core |
| 0x153e8[2] | pending KeyOn mask per core |
| 0x153f0[2] | pending KeyOff mask per core |
| 0x153f8[2] | keyed-on mask per core |
| 0x15400[2] | keyed-off mask per core |
| 0x190f0 | effect nodes, 64 x 28 bytes (+0 flags: bit0 used, bit2 auto-pan, bit31 busy; +4 s16 countdown; +6 s16 mode; +8 next; +0x0c callback; +0x14 s16 step; +0x16 s16 period; +0x18 s16 target) |

Pan table: `tab[i] = (floor(16383 cos(i * 0.5 deg)), floor(16383 sin(i * 0.5 deg)))` for i = 0..179, **except
tab[1].R = 182** (the formula gives 142). i = 90 is (11584, 11584).

#### 1.5 Locks

- `lock()` 0x1630: if flag clear, set it, return 1; else return 0. `unlock()` 0x16a0: clear the flag (unconditionally,
  even if this caller did not take it), then while missed > 0 and suspend == 0: missed--, run the tick.
- `suspend()` 0x5430: count++. `resume()` 0x544c: if count > 0: count--; if it reached 0: while missed > 0: missed--,
  run the tick. (It does not test the lock flag.)
- The tick, when the lock flag or the suspend count is non-zero, only does missed++ (1.6, 4.1).

PlaySound's voice loop runs under `lock`; StopSound, StopAllSounds, SetSoundParams' sub-calls and the set-pitch calls
run under `suspend` (and their inner voice loops under `lock`). A timer tick that falls inside these regions is run
at the `unlock`/`resume` that ends them, *inside the command*.

### 2. Voices

#### 2.1 Allocation `allocVoice(group, prio)` 0x1778 (prio = the tone's priority byte, sign-extended)

```
if split(0x14a4c) == 0:  lo = 0,  hi = 48
elif group == 1:         lo = 0,  hi = 24     (core 0 only)
else:                    lo = 24, hi = 48     (core 1 only)

## pass 1: first free voice, ascending
for v in lo..hi-1:
    if V[v].state == 0:
        V[v].state = 2; V[v].age = now; V[v].prio = (u8)prio; V[v].group = (u8)group
        return v

## pass 2: the victim = lowest priority, then oldest, then lowest index
c = lo
for v in lo+1..hi-1:
    if V[v].prio < V[c].prio  (unsigned): c = v
    elif V[v].prio == V[c].prio and V[v].age < V[c].age (unsigned): c = v
if prio < V[c].prio  (signed new prio vs unsigned stored byte): return -1
if V[c].prio == 127: return -1
if V[c].cb: V[c].cb(c, V[c].owner, 1)            # reason 1: stolen
unlinkVoice(c)                                   # 0x295c: out of the active list, state = 0
V[c].state = 2; V[c].age = now; V[c].prio = (u8)prio; V[c].group = (u8)group; V[c].cb = 0
return c
```

Notes:
- Every voice in range is a candidate in pass 2 whatever it is doing (playing, releasing after a KeyOff with its
  callback already cleared, reserved state 3). Releasing voices are **not** preferred.
- Equal priority steals (the new tone's priority >= the victim's); the victim is the oldest by `age`, ties to the
  lowest index. `age` is refreshed at KeyOn setup (2.2), so all voices started in the same tick tie.
- The stolen voice is neither keyed off nor silenced here; its new parameters are written immediately by the KeyOn
  setup and the new KeyOn goes out at the end of the next tick. Its `lastEnvx`/`silentCount` are kept.
- A negative tone priority can never steal (it is < any unsigned byte); priority 127 voices are never stolen.

#### 2.2 KeyOn setup `keyOnVoice(v)` 0x19b8 (called right after the voice's fields are filled)

```
V[v].age = now
batch (sceSdProcBatch, 8 entries, in this order):
  1. param VOLL  (core|ch<<1|0x000) = (u16)groupScale(V.volL, V.group) >> 1
  2. param VOLR  (|0x100)           = (u16)groupScale(V.volR, V.group) >> 1
  3. switch VMIXL (core|0x1800)     = sceSdGetSwitch(core|0x1800) | 1<<ch      (read now, before the batch)
  4. switch VMIXR (core|0x1a00)     = sceSdGetSwitch(core|0x1a00) | 1<<ch
  5. param PITCH (|0x200)           = voicePitch(V.tone, V.pb, V.pm, V.note, V.fine)   (3.1)
  6. addr  SSA   (|0x2040)          = tone+0x10
  7. param ADSR1 (|0x300)           = tone+0x0a
  8. param ADSR2 (|0x400)           = tone+0x0c
if tone.flags & 1: reverbMask[core] |= 1<<ch  else reverbMask[core] &= ~(1<<ch)
pendingKON[core] |= 1<<ch
linkVoice(v)        # 0x2918: V.next = 0, V.state = 1, appended at the TAIL of the active voice list
```

The KeyOn itself happens at the end of the next tick that runs (4.3).

`groupScale(vol, group)` 0x8124:
```
x = trunc(vol * groupVol[group] / 1024)          (vol is the s16 voice volume)
s = (x < 0) ? -1 : 1
r = s * trunc(x*x / 32512)
return (s16)r
```
So with groupVol 1024 and vol 32512 (127 << 8) the register value is (32512 >> 1) = 0x3f80. A negative result
written as `(u16)r >> 1` is a negative 15-bit volume (phase inverted).

#### 2.3 Voice-level helpers

- `freeVoice(v)` 0x1fc0 (tick path "released"): if V.prio != 127: unlinkVoice(v) (state 0). Then if V.cb:
  `cb(v, owner, 2)`; V.cb = 0; keyedOff[core] &= ~bit. (A priority-127 voice stays linked with state 1 for good:
  it is never reused unless released by the voice-release command 0x1744.)
- `endVoice(v)` 0x214c (tick path "silent too long"): if V.state == 1 and V.cb: `cb(v, owner, 3)`. V.cb = 0.
  pendingKON[core] &= ~bit; pendingKOFF[core] |= bit. (The voice stays linked; it is freed by `freeVoice` once
  keyed off and silent.)
- `keyOffMask(m[2])` 0x224c (normal stop): for v = 0..47 with bit set in m and V.state == 1:
  pendingKOFF[core] |= bit; if V.cb: `cb(v, owner, 3)`; V.cb = 0; pendingKON[core] &= ~bit.
- `silenceMask(m[2])` 0x239c (immediate stop): for v = 0..47 with bit set in m (any state):
  if V.state == 1 and V.cb: `cb(v, owner, 3)`; V.cb = 0; if V.prio != 127: unlinkVoice(v) (state 0);
  ProcBatch {VOLL = 0, VOLR = 0}; pendingKON[core] &= ~bit. **No KeyOff** (keyed-on/keyed-off masks unchanged).
- `pauseMask(m)` 0x252c: ProcBatch {VOLL = 0, VOLR = 0, PITCH = 0} per voice. `resumeMask(m)` 0x2604: per voice
  ProcBatch {VOLL, VOLR as in 2.2, PITCH = voicePitch(V...)}.
- `unlinkVoice` 0x295c: V.state = 0; remove from the singly linked active list (if it is the head, head = V.next;
  otherwise find the predecessor; not found = nothing). V.next is not cleared (so a list walk that unlinks the
  current node can continue through it).

#### 2.4 The program voice callback 0x7bc8 `cb(v, h, reason)`

Ignores `reason`. `h.voiceMask[core] &= ~(1<<ch)`; if both masks are now 0: `freeHandler(h, 0)` (5.2).
So a program sound ends when its last voice is stolen (1), released (2) or ended/stopped (3).

### 3. Pitch and volume

#### 3.1 `voicePitch(tone, pb, pm, note, fine)` = 0x2878 then 0x27d0

```
x = note*128 + fine + pm                         # all as ints (note, fine s8; pm s16)
if pb >= 0: x += trunc(tone.bendUp(+9)   * (pb*128) / 32767)
else:       x += trunc(tone.bendDown(+8) * (pb*128) / 32768)
n = trunc(x / 128);  f = x - n*128              # f may be negative
cn = tone.centreNote(+2) (s8); cf = tone.centreFine(+3) (s8)
if cn >= 0:  p = sceSdNote2Pitch(cn, cf, (u16)n, (s16)f) & 0xffff;  p = floor(p * 44100 / 48000)
else:        p = sceSdNote2Pitch(-cn, cf, (u16)n, (s16)f) & 0xffff  # no conversion
return p & 0xffff
```
(Note: the 44.1 kHz conversion applies to a **non-negative** centre note; a negative centre note is negated and
used unconverted. 15.12 of libraries.md says the opposite and should be corrected.)
`(u16)` of cn/cf/n is the low halfword of the sign-extended value, as passed to libsd.

#### 3.2 `voiceVolPan(master=127, vol, pan, progVol, progPan, toneVol, tonePan, out)` 0x7dc0

`out` = &V.volL / V.volR, which hold the voice's **previous** values on entry (0, 0 at a play).
```
t = trunc((vol << 8) * toneVol / 127)
t = trunc(t * progVol / 127)
t = trunc(t * master / 127)                     # master is always 127 here: no change
if t == 0: out = (0, 0); return
if mode == 1: out = (t, t); return             # mono
a = pan + tonePan + progPan
if a >= 360: repeat a -= 360 while a >= 360    # no handling of negative a
a = (a < 270) ? a + 90 : a - 270                # a in 0..359 for a >= 0 (a < -90 indexes before the table)
oldL, oldR = out
if a < 180:
    L = trunc(t * tab[a].L / 16383); R = trunc(t * tab[a].R / 16383)
    if oldL < 0 and oldR < 0: L = -L; R = -R
    elif (oldL < 0) != (oldR < 0):              # mixed signs: follow the sign of the larger magnitude
        s = (|oldR| < |oldL|) ? sign(oldL) : sign(oldR);  L *= s; R *= s
else:
    a -= 180
    R = trunc(t * tab[a].L / 16383); L = trunc(t * tab[a].R / 16383)   # swapped
    if mode != 2:                               # rear half: invert one side
        if oldL >= 0 and oldR >= 0: (R < L) ? R = -R : L = -L
        elif oldL >= 0 and oldR < 0: R = -R
        elif oldL < 0 and oldR >= 0: L = -L
        else: (L < R) ? R = -R : L = -L
out = (L, R)
```
Pan 0 = centre, 90 = full right, 270 = full left, 180 = rear centre. TMB sets mode 0x0d (neither 1 nor 2).

### 4. The tick 0x54b8 (240 Hz)

#### 4.1 Order

```
if guard: return;  guard = 1
if lock != 0 or suspend != 0: missed++; guard = 0; return
now++
for each voice v in the active voice list, from the head (oldest link first):   # 4.2
    ...
handlerTick()        0x70a4  (4.4)
flushKeyOff()        0x1ed0  (4.3)
flushKeyOn()         0x1db0  (4.3)
0x86ac               (delayed effect-volume restores per core: counters 0x150c0/0x150c4 -> EVOL L/R 0xb80|core,
                      0xc80|core from 0x150b0.., sceSdSetEffectAttr? (libsd:11) (core+2, 1), 0xe628; then 0x11e1c,
                      SBlk processing; no voice-lifetime effect for programs)
guard = 0
```

#### 4.2 The voice loop

```
v = node.index; bit = 1 << ch
if pendingKON[core] & bit: continue                    # not keyed on yet
e = sceSdGetParam(core | ch<<1 | 0x500)               # ENVX
if (e & 0xffff) != 0: continue                         # still sounding; nothing recorded
## ENVX == 0
if keyedOff[core] & bit:
    freeVoice(v)                                       # reason 2 to the owner if it still has a callback
elif keyedOn[core] & bit:
    if lastEnvx[v] != 0: silentCount[v] = 4            # never true: lastEnvx is only ever written with 0 (below)
    else:
        silentCount[v] -= 1  (u8 wrap)
        if (s8)silentCount[v] == 0: endVoice(v)        # reason 3, KeyOff queued (flushed this same tick)
    lastEnvx[v] = e  (= 0)
## else (neither mask): nothing
next = node.next   (read after the call; unlinking does not clear it)
```

So a voice ends 256 silent (ENVX == 0) ticks after its counter last was 0 — and since the counter is per hardware voice
and survives reuse, a voice freed or stolen mid-count leaves the remainder to its next user (e.g. 10 silent ticks,
then a KeyOff by StopSound: the next sound on that voice ends after 246 silent ticks). Ticks where ENVX is non-zero
do not touch the counter.

#### 4.3 KeyOff and KeyOn flush

`flushKeyOff` 0x1ed0: if pendingKOFF[0] | pendingKOFF[1]: `sceSdSetSwitch(0x1600, pkoff[0])`,
`sceSdSetSwitch(0x1601, pkoff[1])` (both, even if one is 0); keyedOn &= ~pkoff; keyedOff |= pkoff; pkoff = 0.

`flushKeyOn` 0x1db0: if pendingKON[0] | pendingKON[1]: one ProcBatch of 6 switch writes, in order: VMIXEL core0 =
reverbMask[0], VMIXER core0 = reverbMask[0], VMIXEL core1 = reverbMask[1], VMIXER core1 = reverbMask[1], KON core0 =
pkon[0], KON core1 = pkon[1]; keyedOff &= ~pkon; keyedOn |= pkon; pkon = 0.

KeyOff is flushed before KeyOn, so a voice stopped and restarted (stolen) in the same tick gets KOFF then KON.

#### 4.4 `handlerTick` 0x70a4

For each handler in the active handler list (head first; next read after processing):
by type (`handle >> 24 & 0x1f`): 0 (program): nothing type-specific; 1, 3: if not paused, `stop = 0x89d0(h)` (MIDI);
2: `stop = (h+0x28 == 0)`; 4: `stop = 0xc980(h)`; 5: `stop = 0x12308(h)`.
If !stop and h.effects (+0x08) != 0 and not paused: `stop = runEffects(h.effects, h)` (6.2).
If stop: `stopHandler(h, 0, 0)` (5.3).

A program handler therefore never ends here: only through its voices' callbacks (2.4).

### 5. Handlers

#### 5.1 Allocation 0x64d8 (interrupts disabled around it)

```
for i in 0..47:
    if H[i].sound == 0:
        H[i].handle = i << 16 | ((H[i].handle + 1) & 0xffff)      # bit31 clear; gen = previous low half + 1
        H[i].flags = 0; H[i]+0x20 = 0; +0x24 = 0; +0x28 = 0
        return &H[i]
return 0
```
Activation 0x6764 (after the play's voice loop): `handle |= 0x80000000`, next = 0, appended at the tail of the
active handler list. So the handle returned is `0x80000000 | slot << 16 | gen` (gen wraps at 16 bits).

#### 5.2 `freeHandler(h, recurse)` 0x67d0

If `h.handle` bit 31 is clear: return (not active). Else (interrupts off): h.sound = 0; clear bit 31; remove h from
the active handler list (if not found there: return); if h.effects: walk the chain (0x726c — it frees nothing: the
nodes stay marked used, a leak) and set h.effects = 0. Then if recurse and h+0x28: freeHandler(h+0x28, recurse).

#### 5.3 `stopHandler(h, recurse, immediate)` 0x6e9c

```
type = h.handle >> 24 & 0x1f
if type == 2: clear bit 1 of byte 6 of *(h.sound+0x18); go on
if type == 4: 0xc748(h, 0); skip the voice part
(type 0, 1, 3, 5: go on)
lock()
if immediate or (h.flags & 2 /*paused*/): silenceMask(h.voiceMask)     # 2.3, reason 3, voices freed now
else:                                    keyOffMask(h.voiceMask)       # 2.3, reason 3, KeyOff at next tick
unlock()                                  # may run missed ticks
freeHandler(h, 0)                         # usually already done by the callback when the mask emptied
## chain links
if h+0x24: (h+0x24)->+0x28 = h+0x28
if h+0x28: (h+0x28)->+0x24 = h+0x24; if recurse: stopHandler(h+0x28, recurse, immediate)
h+0x28 = 0
```

#### 5.4 Handle lookup 0x6900

`type = handle >> 24 & 0x1f`, `slot = handle >> 16 & 0xff` (no bound check). Type 0: `&H[slot]` if
`H[slot].handle == handle` (whole word, so bit 31 = still active and the generation must match), else 0. Types 1,
2, 4, 5 the same on their pools; other types: 0.

### 6. PlaySound (commands 0x11, 0x12)

#### 6.1 Commands

Request words: bank, sound index, volume, pan, pitch modifier (low half, s16), pitch bend (low half, s16).
0x11 (0x300) writes PlaySound's result to its reply slot; 0x12 (0x35c) calls the same and writes nothing (the slot
keeps the driver's last result).

#### 6.2 Dispatch 0x5730 `play(bank, idx, vol, pan, pm, pb)`

```
if bank == 0: return 0
if bank.magic == 'SBlk': return 0x11fe0(...)
if idx >= bank.soundCount (s16 +0x14) or idx < 0: return 0
snd = bank.sounds + idx*28
if snd.bank == 0: return 0
switch snd.type: 1, 2, 3 -> playProgram 0x7460;  4 -> 0x87a0 (MIDI);  5 -> 0x9b10;  else (0, <0, >5) -> 0
```

#### 6.3 `playProgram(snd, vol, pan, pm, pb)` 0x7460

```
if snd.type == 2: stopSameSound(snd)                      # 0x6fd0, 6.4 — before anything else
if vol == 0x7fffffff: vol = 1024
hv = asr(vol * snd.vol, 10);  if hv >= 128: hv = 127      # no lower clamp (negative vol stays negative)
if pan == -1 or pan == -2: pan = snd.pan
n = selectTones(snd.bank, snd.program, snd.note, list)    # 6.5
lock()
h = 0; first = true
for i in 0..n-1:
    tone = list[i]
    v = allocVoice(snd.group, tone.priority)               # 2.1 (may steal, may free another handler)
    if v == -1: continue
    if first:
        h = allocHandler()                                 # 5.1, AFTER the first voice is allocated
        h.sound = snd; h.sndVol = snd.vol; h.sndPan = snd.pan; h.vol = hv; h.pan = pan; h.pm = pm
        h.note = snd.note; h.fine = snd.fine; h.pb = pb; h.group = snd.group
        h.flags = 0; h.effects = 0; h+0x34 = 0
        first = false
    h.voiceMask[core] |= 1 << ch
    V.owner = h; V.cb = 0x7bc8; V.tone = tone; V.note = snd.note; V.fine = snd.fine; V.pb = pb; V.pm = pm
    V.prio = tone.priority; V.group = snd.group; V.volL = V.volR = 0
    voiceVolPan(127, hv, pan, prog.vol, prog.pan, tone.vol, tone.pan, &V.volL)    # 3.2
    keyOnVoice(v)                                          # 2.2
unlock()                                                   # missed ticks run here (handler not yet active)
if h == 0: return 0
activate(h)                                                # 5.1
return h.handle
```

- One voice per tone whose key range holds the sound's note; every voice gets the sound's note/fine (pitch differs
  only through each tone's centre note/fine and bend ranges).
- The play returns 0 for a non-empty sound when no tone matches, or when every tone's `allocVoice` fails (all
  voices in range busy with a higher priority than the tone's, or the lowest is 127, or the tone's priority is
  negative and nothing is free). Then no handler is taken (no generation consumed).
- If `allocHandler` finds no free slot (48 active program sounds) the code continues with h = 0 (it writes the
  handler fields to IOP address 0..0x34 and the voices get owner 0 with the callback set); the play returns 0 and
  the voices play unowned. Undefined behaviour in the original; a reimplementation should treat it as "voices start,
  result 0" or refuse — no record shows it.
- Because the handler is allocated after the first voice, a handler freed by that voice's steal (its last voice
  taken) can be the slot this play receives.
- Edge: a later tone of the same play can steal an earlier voice of the same play (all same `age`; only if it is the
  lowest priority in range). The callback then clears that bit; if the mask becomes empty, `freeHandler` returns at
  once (bit 31 not yet set), and the handler is then activated with an empty mask and never ends by itself.
- A missed tick that runs at the `unlock` skips the new voices in its voice loop (their KON is pending) and then
  flushes their KeyOn: the voices key on inside the play command.

#### 6.4 Type 2: `stopSameSound(snd)` 0x6fd0

For each handler in the active handler list (head first): if `h.sound == snd`: `stopHandler(h, recurse=1,
immediate=0)` (via 0x6a68 by handle). I.e. the earlier instances' voices get KeyOff (pending, flushed at the next
tick), their callbacks are cleared with reason 3, and the handlers are freed immediately — their handles stop being
valid before the new play allocates its handler (so the new play can reuse the slot).

#### 6.5 `selectTones(bank, p, note, out)` 0x7c58

```
if p >= bank.programCount (s16 +0x16): return 0        # no test for p < 0
prog = bank.programs + p*8; t = prog.tones
n = 0
for i in 0..prog.toneCount-1 (s8):
    if t[i].keyLow <= note <= t[i].keyHigh (signed bytes): out[n++] = &t[i]
return n
```
The caller's buffer holds 16 pointers; more than 16 matching tones would overrun its stack (not seen).

### 7. The handle commands

All of these take a handle; type = `handle >> 24 & 0x1f` (0 for program sounds).

#### 7.1 StopSound (0x15) 0x586c — no result written

`suspend(); h = lookup(handle); if h: stopHandler(h, 1, 0); resume()`.
Effect: KeyOff queued for the sound's voices (sent at the next tick's flush), handler freed now (the handle is
invalid from this command on), voices stay linked until the tick sees them keyed off with ENVX 0 (then `freeVoice`,
no notification since the callback was cleared). A paused sound is silenced and freed immediately instead.

#### 7.2 StopAllSounds (0x18) 0x6e24 — no result written

```
suspend()
for h in active handler list (head first): if h+0x24 == 0: stopHandler(h, 1, 1)    # immediate
silenceMask({0xffffffff, 0xffffffff})       # every voice 0..47: callback (state 1) reason 3, unlink unless prio 127,
                                            # VOLL = VOLR = 0, pending KON cleared; no KeyOff
resume()
```
After it every voice (except priority-127 ones) is free, but voices that were keyed on stay keyed on in the hardware
at volume 0 (the keyed-on mask keeps their bits; a looping sample keeps running silently until the voice is reused).

#### 7.3 SoundIsStillPlaying (0x19) 0x58b4 — result written

`if handle == 0: 0; else lookup(handle) ? handle : 0`. No suspend. Only the handler's own state counts: a program
sound "plays" from its play until its handler is freed (last voice stolen/ended/released, or stopped).

#### 7.4 SetSoundPitchModifier (0x20) 0x5e60 — no result written

`suspend()`; by type: 0 -> 0x7a54: `h = lookup(handle); if h: h.pm = pm (s16); repitch(h)`; 1 -> 0x9970; 2 -> 0x9e8c;
5 -> 0x12938; others nothing; `resume()`.

`repitch(h)` 0x7a8c: `took = lock()`; for each owned voice v (ascending 0..47, from h.voiceMask): V.pb = h.pb;
V.pm = h.pm; `sceSdSetParam(core|ch<<1|0x200, voicePitch(V.tone, h.pb, h.pm, h.note, h.fine))` — written
immediately, not batched. `if took: unlock()`.
(Pitch bend, 0x5dc4 type 0 -> 0x7a1c: h.pb = pb; repitch. Type 1 ignores it; type 5 -> 0x12900.)

#### 7.5 SetSoundParams (0x21) 0x5aac — result written

Request: handle, mask, vol, pan, pm, pb (pm and pb are the low halves).
```
h = lookup(handle); if !h: return 0                 # decided before any change; no suspend around this lookup
if !(mask & 1): vol = 0x7fffffff
p = (mask & 2) ? pan : -2
if mask & 3:  setVolPan(handle, vol, p)              # 0x59c4, 7.6
if mask & 4:  autoPan(handle, pan, dir=0, time=30, kind=4)   # 0xabc0, section 8
if mask & 8:  setPitchModifier(handle, (s16)pm)      # 0x5e60 (7.4)
if mask & 0x10: setPitchBend(handle, (s16)pb)        # 0x5dc4 (repitch)
return handle
```
TMB's masks (match1p): 0x15, 0x05, 0x0d, 0x10, 0x1d, 0x11, 0x01.

#### 7.6 `setVolPan(handle, vol, pan)` 0x59c4 -> type 0: 0x77ac

`suspend()`; dispatch by type (0: 0x77ac, 1: 0x96fc, 2: 0x9d88, 4: 0xfc20, 5: 0x126bc, 3: nothing); `resume()`.
0x77ac:
```
h = lookup(handle); if !h: return
if vol < 0:                 h.vol = -vol              # taken as is, no sound-volume scaling
elif vol != 0x7fffffff:     h.vol = (s16) asr(vol * snd.vol, 10)

if pan == -1: h.pan = snd.pan  elif pan != -2: h.pan = pan

for each owned voice v ascending:

    sceSdSetParam(core|ch<<1|0x000, (u16)groupScale(V.volL, snd.group) >> 1)
    sceSdSetParam(core|ch<<1|0x100, (u16)groupScale(V.volR, snd.group) >> 1)
if took: unlock()
```

### 8. Auto-pan (SetSoundParams mask 4): 0xabc0 and its tick callback 0xaee8

`autoPan(handle, target, dir, time, kind)` with dir = 0, time = 30, kind = 4:
```
suspend(); h = lookup(handle); if !h: resume; return
d = target - h.pan
auto = (dir == 0); if auto: dir = 1
if dir > 0 and d < 0: d += 360
if dir < 0 and d > 0: d -= 360
if auto and |d| >= 181: dir = -dir; d -= 360            # take the short way round
if kind == 4: time = trunc(time * |d| / 180)            # 30 ticks per half turn
if time == 0: removeEffect(h, 4); setVolPan(handle, 0x7fffffff, target); done   # immediate
if d == 0:    removeEffect(h, 4); done
e = findEffect(h, 4)                                     # first node in h.effects with flags & 4
if e: e.flags |= 0x80000000 (busy while editing)
else:
    e = allocNode()                                      # first of 64 at 0x190f0 with flags bit0 clear;
                                                         # sets flags = 1, next = 0
    if !e: setVolPan(handle, 0x7fffffff, target); done   # pool exhausted: immediate
    new = true; e.callback = 0xaee8; e.flags |= 4
if |d| < time: e.mode = 1; e.period = e.count = |trunc(time / d)|; e.step = (d >= 0) ? 1 : -1
else:          e.mode = 0; e.count = 0; e.step = trunc(d / time)
e.target = target
if new: append e at the tail of h.effects   else: e.flags &= 0x7fffffff
resume()
```
`runEffects(node, h)` 0x71c8 (from `handlerTick`, not when paused): recursively processes the chain from the **tail**:
`if node.next and runEffects(node.next, h) == 1: return 1`; if node.flags bit 31: return 0; if node.mode == 1:
node.count--; if node.count == 0: return node.callback(node, h); return 0. (mode 0: count stays 0, the callback runs
every tick.)

Callback 0xaee8 (always returns 0):
```
step = e.step; p = h.pan
if |step| >= 2: np = (s16)(((u32)(p*32 + step)) >> 5)      # LOGICAL shift: a positive step < 32 leaves the pan
                                                          # unchanged (np == p) — a 989SND bug, see open questions
else:           np = (s16)(p + step)
cmp = target
if np >= 360 and target < p: cmp = target + 360
elif np < 0 and p < target:  cmp = target - 360
if (step > 0 and cmp < np and p < cmp) or (step < 0 and np < cmp and cmp < p): np = target   # passed it
else: if np < 0: np += 360 elif np >= 360: np -= 360
setVolPan(h.handle, 0x7fffffff, np)                       # 7.6: voices' volumes rewritten now
if np == target: removeNode(h, e)                         # 0x73b0: flags bit0 cleared, unlinked
elif e.mode == 1: e.count = e.period
```
Since with time = 30 every |d| >= 6 gives mode 0 with step = trunc(d / trunc(|d|/6)) (6..11 in magnitude), a
positive auto-pan never moves with this code and its node stays until the next SetSoundParams re-targets it, the
sound ends (then the node leaks, 5.2) or a pan within 5 degrees removes it; a negative one moves 1 degree per tick
(for p*32 + step >= 0). Lifetimes are not affected (the callback never asks for a stop).

### 9. Summary of the lifetime rules a native driver must reproduce

1. A program play takes one voice per matching tone (2.1 order and stealing), the handler after the first voice,
   the lowest free handler slot with gen+1; the handle is valid until the handler is freed.
2. The handler is freed when the last of its voices is stolen (in a later play's allocation), ended by the silent
   counter (the tick: 256 silent ticks counted per hardware voice, the count surviving reuse), released (rarely
   reaches a live callback), or the sound is stopped (StopSound, StopAllSounds, a type 2 replay of the same sound,
   or an effect asking for a stop).
3. KeyOn of a play's voices: end of the next tick that runs (possibly a missed tick run inside the play).
   KeyOff of stopped/ended voices: end of the tick (or the next tick). A voice is reusable without stealing only once
   `freeVoice` ran (keyed off and ENVX 0 at a tick) or after `silenceMask`.

### 10. Open questions / not verified

1. Tone `+0x10`: whether the loader rewrites it to an absolute sound-memory address (the play writes it to SSA as is).
2. The 989SND bug readings should be double-checked against the replay: (a) auto-pan `(p*32+step)>>5` with logical
   shift (positive sweeps stall); (b) `freeHandler` leaks effect nodes (0x726c walks the chain and frees nothing),
   so after 64 leaked nodes every masked-4 pan becomes immediate; (c) `lastEnvx` is only ever written with 0, so the
   counter reset to 4 never fires.
3. Voices of priority 127 (tone priority 127, or reserved voices) are never unlinked by `freeVoice`/`silenceMask`:
   permanently busy until command 0x1744. Not seen in TMB's banks? (unchecked).
4. Pool-full play (48 active program handlers) writes through a null handler: undefined; behaviour in the records
   unknown.
5. 0x86ac's libsd:11 call (taken as sceSdSetEffectAttr-like with (core+2, 1)) and 0x11e1c (SBlk tick) were not
   followed; they do not touch program voices as far as read.
6. What the tick thread's preemption means for a reimplementation: inside the commands, any tick due while neither
   the lock nor the suspend count is held would run at that point of the command (e.g. during PlaySound's
   `stopSameSound`, before its `lock()`); with them held it runs at the `unlock`/`resume`. The IOP timing model
   (iop-timing.md) decides which ticks fall where.
7. Types 1 (MIDI 0x87a0), 4 (streams) and 5 (0x9b10) plays, the MIDI voice paths (0x9124, 0x9424, 0x94f8 use
   allocVoice/endVoice), and group pause/resume (0x6c14, 0x6d5c; pause sets flags bit 1 and writes VOL 0, PITCH 0)
   are only outlined here.
8. Command 0x0d (0x161c) sets the voice-range split flag; TMB's traces never send it (all 48 voices in one range).


## Part B: the MIDI sound path (sound type 4, handler type 1)

Clean-room behavioural spec, written from the module listing (module offsets), the module's `.data` and bank
memory as the analysis replay (the analysis replay) loads them. It extends Part A and reuses its names and
sections: `allocVoice` (2.1), `keyOnVoice` (2.2), `freeVoice`/`endVoice`/`keyOffMask`/`silenceMask`/`pauseMask`/
`resumeMask`/`unlinkVoice` (2.3), `voicePitch` (3.1), `voiceVolPan` (3.2), `groupScale` (2.2), the tick (4),
`handlerTick` (4.4), handlers, `freeHandler`, `stopHandler`, lookup (5), `selectTones` (6.5), `lock`/`unlock`/
`suspend`/`resume` (1.5), the voice table `V` at 0x16aa0, the active voice list (head 0x14a54), the active handler
list (0x14ac0). "trunc" = integer division toward zero, "asr" = arithmetic shift right, "divu" = unsigned 32-bit
division, "(u32)x" = the low 32 bits of x. The magic-number divisions in the code were checked to be the exact
divisions written here.

Naming: a **sound** of type 4 is played by a **MIDI handler** (handle type 1, prefix 0x01000000, so active handles
are 0x81ssgggg). The sequencer at 0x89d0 is also run for handler type 3 (the per-sub-sequence handlers of sound
type 5, 0x9b10), which TMB never uses (no type 5 sound in any of its banks).

### 1. Data in the bank

#### 1.1 The MIDI chunk (bank file chunk 2) and its loading (0x3678, 0x4498)

The chunk starts with 16 bytes: u32 (2), u32 (1), u32 `dataOffset` (0x10), u32 `dataSize`. Words 0 and 1 are not
checked. The loader allocates `dataSize` bytes of IOP heap (the "next block" of libraries.md 15.4), reads
`dataSize` bytes at chunk + `dataOffset` into it, and calls `loadMidiBlock(block)` (0x4498) on it once. The chunk
therefore holds exactly one top-level block, an `MID ` block or an `MMID` block.

**`MID ` block** (one sequence):

| off | type | meaning |
|---|---|---|
| 0x00 | u32 | magic 0x2044494d (`'MID '`) |
| 0x04 | u32 | (1 in the low byte; byte 7 varies, unused by this path) |
| 0x08 | u32 | block id (what a sound's +0x0c names); 0 for a sub-block of an `MMID` |
| 0x0c | ptr | link in the MIDI block list (0x14a70); the loader zeroes it, then appends the block |
| 0x10 | u32 | id of the bank whose programs the sequence plays (compared with a bank's u32 at +0x0c) |
| 0x14 | ptr | that bank (resolved at load) |
| 0x18 | u32 -> ptr | offset of the event data from the block start; relocated to a pointer at load |
| 0x1c | ptr | the parent `MMID` block (0 for a top-level `MID `) |
| 0x20 | u32 | initial tempo, microseconds per quarter note |
| 0x24 | u16 | PPQ (MIDI ticks per quarter note; 480 in every TMB sequence) |
| 0x28 | | the event data in TMB's files (offset 0x18 = 0x28) |

**`MMID` block** (a set of sequences): +0x00 magic 0x44494d4d (`'MMID'`), +0x07 s8 `count`, +0x08 u32 block id,
+0x0c list link, +0x10 u32 `sub[count]`: offsets of `MID ` sub-blocks from the `MMID` start.

`loadMidiBlock(b)` 0x4498:
```
if b.magic == 'MID ':
    b.bank = findBankById(b.bankId)       # 0x435c: first bank in list 0x14a68, then list 0x14a6c (links at bank+0x30)
                                          # whose u32 at +0x0c == id; else 0
    b.link = 0; b.parent(+0x1c) = 0; b.data(+0x18) += b
    appendMidiBlock(b)                    # 0x46c4: at the tail of the list at 0x14a70 (link +0x0c)
elif b.magic == 'MMID':
    b.link = 0; appendMidiBlock(b)
    for i in 0..count-1 (s8 count):
        b.sub[i] += b                     # pointer to the sub-block
        loadMidiBlock(b.sub[i])           # recursion: the sub-block is relocated, gets its bank, is appended too
        b.sub[i].parent = b
## other magic: nothing
```
(A sub-block's own +0x08 is 0 and its `bankId` is the parent's bank id in TMB's files.)

#### 1.2 The type-4 sound record (28 bytes)

| off | type | meaning |
|---|---|---|
| 0x00 | s32 | 4 |
| 0x04 | ptr | owning bank (0 = not resolved: play answers 0) |
| 0x08 | u32 | the owning bank's id (e.g. `'shmd'`, `'EXPL'`) |
| 0x0c | u32 | id of the `MID `/`MMID` block it plays |
| 0x10 | s16 | volume (0..1024 scale like program sounds; TMB: 0x3c..0x7f) |
| 0x12 | u8 | **loop count**: 0 = forever, n = play the sequence n times (see 3.4 for 129..255) |
| 0x13 | s8 | volume group (voice range + group volume, as for programs) |
| 0x14 | s16 | pan in degrees (used when the play passes pan -1 or -2) |
| 0x16 | s8 | index of the sub-sequence when +0x18 is an `MMID` |
| 0x17 | u8 | unused |
| 0x18 | ptr | the MIDI block, resolved by the bank resolver (0x407c, the sound loop: for types 4 and 5, +0x18 = the first block in list 0x14a70 whose u32 at +0x08 equals +0x0c, else 0) |

Command 0x1a (IsSoundALooper, 0x58f0) answers `snd+0x12 == 0` for a type-4 sound.

Examples (TMB): shell music bank 0x80cc4 sound 0 = `04000000 c40c0800 'shmd' 'shmd' 7f00 00 01 4000 00 00
c0120800` (volume 127, loop forever, group 1, pan 64, `MID ` at 0x812c0: tempo 722891, PPQ 480, data 0x812e8);
match1p bank 0xe7684 sounds 0xa/0xb/0xc/0xd/0xf play sub-sequences 0/1/2/3/4 of `MMID` `'ENGM'` (0xe7b50); 0xb
(volume 60, loop count 0: the looping engine sound), 0xd and 0xf (loop count 1: one-shot).

#### 1.3 `midiBlockOf(snd)` 0x8944

```
b = snd+0x18; if b == 0: return 0
if b.magic == 'MID ': return b                          # +0x16 ignored
## anything else is taken as an MMID
if (s8)b.count - 1 < (s8)snd+0x16: return 0             # no test for a negative index
return b.sub[(s8)snd+0x16]
```

#### 1.4 The event data

Standard-MIDI-file-like track bytes, one track, interpreted by 3.3:

- every event is a variable-length delta (7 bits per byte, MSB first, bit 7 = more; 0x9024), then the event;
- **status**: if the byte at the pointer has bit 7 set it becomes the running status and is consumed; otherwise the
  running status is reused. **Every** status byte >= 0x80 sets the running status, including 0xff (meta) and 0xf0
  (sysex): an event after a meta event without a status byte is read as another meta event (see 3.3, "running
  status after a meta event");
- meta event: `ff tt ll data` with **no** varlen length handling: only `ff 2f` (end of track: the bytes after `2f`
  are not read) and `ff 51 03 t2 t1 t0` (tempo) are understood;
- sysex: `f0 ... f7` with **no** length: skipped to the `f7`, or `f0 75 ...` = 989's own command language (0x9f00);
- channel events 0x8n, 0x9n, 0xbn, 0xcn, 0xdn, 0xen.

TMB's data uses: 0xcn program change, 0x9n note on (velocity 0 = note off in the in-game sequences), 0x8n note off
(shell music), 0xen pitch bend (shell music: channels 0, 8-11, 15), `ff 51` (one at delta 0 in every sequence),
`ff 2f`. No controller, no channel pressure, no sysex. One sequence (bank 0xe93f4 `'CHAM'` sub 4, `MID ` 0xe97ec)
has `... ff 51 03 0a 2c 2a | 85 77 39 00 | 00 ff 2f`: its note-off `39 00` (running status 0x90 meant) is read as an
unknown meta event (see 3.3).

#### 2.2 Allocation 0x65ac (interrupts disabled around it)

```
for i in 0..31:
    if M[i].sound == 0:
        M[i].handle = 0x01000000 | i<<16 | ((M[i].handle + 1) & 0xffff)    # bit 31 clear
        M[i].flags(+0x16) = 0; +0x20 = 0; +0x24 = 0; +0x28 = 0

return 0
```
Same lowest-free-slot, generation-counting scheme as programs (the shell music is 0x81000002). The voice masks are
not reset: they are empty by then, because every path that drops one of the handler's voices calls its callback

### 3. Play and sequencer

#### 3.1 `playMidi(snd, vol, pan, pm)` 0x87a0 (from PlaySound 0x5730 for type 4; the pitch-bend argument is not passed)

```
b = midiBlockOf(snd)                      # 1.3
if b == 0: return 0
if b.bank (+0x14) == 0: return 0
h = allocMidiHandler()                    # 2.2
if h == 0: return 0xffffffff              # pool full: the play answers -1 (not 0)
if vol == 0x7fffffff: vol = 1024
h.vol = (s16) asr(vol * snd.vol, 10); if h.vol >= 128: h.vol = 127   # no lower clamp
h.pan = (pan == -1 or pan == -2) ? snd.pan : pan
h.pm = (s16)pm
h.loops(+0xb4) = snd+0x12; h.sound = snd; h.sndVol = snd.vol; h.effects = 0; h.flags = 0; h.sndPan = snd.pan
h.group = snd.group
## 0x88e4:
h.bank = b.bank; h.loopStart = h.ptr = b.data; h.rem = 0; h.tempo = b.tempo; h.ppq = b.ppq
resetChannels(h)                          # 0x9534: mute = 0; for ch 0..15: prog 0, vol 127, pan 0, bend 0; sustain = 0
h.flags2(+0xb2) |= 1                      # first tick pending
activate(h)                               # 0x6764: handle |= 0x80000000, appended at the tail of the handler list
return h.handle
```
No lock, no suspend, no voice is touched: nothing sounds until the first tick that runs after the play. No
`stopSameSound`, no tone selection at play time.

#### 3.2 Time base

`rate` (0x14a90) = `divu(100000000, trunc(240 * 999 / 10))` = 100000000 / 23976 = **4170** (microseconds per driver
tick, set at module start, 0x4894-0x4908; 240 from 0x4c70). For a tempo `T` (us per quarter) and PPQ `P`:

```
step(T, P) = divu(rate * 1000, divu(T, divu(P, 10)))      # 100 x MIDI ticks per driver tick
             # P 480: divu(P,10) = 48; T 722891: 15060; step = 4170000 / 15060 = 276
             # (a T below divu(P,10) divides by zero: IOP break)
ticksFor(n): u = divu((u32)(T * n), P)                    # microseconds, (u32) = low 32 bits of the signed product
             c = divu(u + rate - 1, rate)                 # ceil(u / rate); u = 0 gives 0
```

#### 3.3 `seqTick(h)` 0x89d0, run by `handlerTick` for an unpaused type-1 handler; returns 1 = stop

```
if busy(0x150f0): return 0                # static re-entrancy guard; never set when entered from the tick
busy = 1
stop = 0
if h.flags2 & 1:                          # first tick after the play
    h.step = step(h.tempo, h.ppq)
    h.runStatus = 0
    (d, len) = varlen(h.ptr)
    h.x = 100*d                           # (u32) arithmetic
    n = trunc(h.x / 100)                  # = d
    h.count = ticksFor(n)                 # with h.tempo, h.ppq   -- no half-tick rounding on the first delta
    h.rem = 0
    h.flags2 &= ~1; h.ptr += len
else:
    h.count -= 1
if h.count != 0: busy = 0; return 0

loop:                                     # events due now
    p = h.ptr
    if p[0] & 0x80: h.runStatus = p[0]; h.ptr += 1; p = h.ptr
    s = h.runStatus; ch = s & 0x0f
    if s == 0xff:                         # meta
        if p[0] == 0x2f:                  # end of track (pointer left on the 0x2f)
            h.loops = (u8)(h.loops - 1)
            if h.loops == 0: stop = 1
            else: h.ptr = h.loopStart; if (s8)h.loops < 0: h.loops = 0
        elif p[0] == 0x51:                # tempo: p[1] (length) ignored, 3 bytes big-endian
            h.tempo = p[2]<<16 | p[3]<<8 | p[4]; h.ptr += 5
            h.step = step(h.tempo, h.ppq)       # count and rem unchanged
        else: (nothing; pointer NOT advanced: the type byte is read next as a delta)
    elif s == 0xf0:                       # sysex
        if p[0] == 0x75:
            q = sysex989(h, p + 1)        # 0x9f00, 989's command language (not used by TMB; not specified here)
            if q == 0: h.ptr = 0; stop = 1
            else: h.ptr = q + 1
        else: skip: h.ptr advances to the first 0xf7 at or after p, then past it
    else switch s & 0xf0:
        0x80: noteOff(h, ch, p[0]); h.ptr += 2                     # velocity ignored
        0x90: if p[1] == 0: noteOff(h, ch, p[0])
              elif !(h.mute >> ch & 1): noteOn(h, ch, p[0], p[1])
              h.ptr += 2
        0xb0: controller(h, ch, p[0], p[1]); h.ptr += 2            # 3.6; may set stop
        0xc0: h.prog[ch] = p[0]; h.ptr += 1
        0xd0: noteOff(h, ch, p[0]); h.ptr += 1                     # channel pressure is taken as a NOTE-OFF of
                                                                   # the note numbered by the pressure value (quirk)
        0xe0: pitchBend(h, ch, p[0], p[1]); h.ptr += 2             # 3.7
        else (0xa0, and 0xf1..0xfe): nothing, pointer not advanced (data bytes then misread as a delta)
    if stop: break
    # the next delta
    (d, len) = varlen(h.ptr)
    x = 100*d + h.rem;  h.x = x
    if x < 0 or x < trunc(h.step / 2):    # signed compare
        h.rem = x; h.x = 0                # due in this same tick (count stays 0)
    if h.x != 0:
        h.count = ticksFor(trunc(h.x / 100))
        h.rem = h.x - h.step * h.count
    h.ptr += len
    if h.count != 0: break
busy = 0
return stop
```
Notes:
- So an event fires at the tick where the countdown reaches 0; its delta, in 1/100 MIDI ticks plus the carried
  remainder, is turned into whole driver ticks rounded **up** (through microseconds), unless it is less than half a
  driver tick (then it fires in the same tick and the whole of it is carried). The carried remainder is
  `x - step*count`, usually negative (the rounding up borrowed time). Example, shell music: first notes at the first
  tick; delta 94 -> x = 9400 (>= 138), u = 722891*94/480 = 141566 us, count = 34, rem = 9400 - 276*34 = 16 (checked
  against the replay's handler state).
- `(u32)(T * n)` wraps for long deltas (T = 722891: n > 5941 MIDI ticks); the wrapped value is used.
- When the countdown is first set on the first tick the first delta is not rounded by the half-tick rule (a delta of
  1 MIDI tick there waits 1 driver tick).
- On a loop (end of track with loops left) the running status, channel state (programs, volumes, pans, bends,
  sustain), tempo, `step` and `rem` all carry over; the first delta of the data is read again by the normal rule.
- End of track while notes still hold voices: the handler stops (3.8), their voices get KeyOff in this same tick.
- **Running status after a meta event** (TMB's `'CHAM'` sub 4, 1.4): after `ff 51 ...` the running status is 0xff;
  `85 77` (delta 759) then `39` is read as meta type 0x39 (unknown: nothing, pointer stays) -> delta 0x39 = 57 is
  read from it, then `00` -> meta type 0 (unknown) -> delta 0 -> `ff 2f` end of track. The note 57 started before is
  therefore never released by the data; it is keyed off when the sequence ends (if its sound plays once) or stays on
  across loops.

#### 3.4 Loop count

`h.loops` starts at sound +0x12. At each end of track: `loops = (u8)(loops - 1)`; 0 -> stop; else jump to the loop
start, and if the new value is >= 128 (negative as s8) it is set to 0. Hence: 0 -> forever (255 -> 0 -> 255...),
1 -> once, n in 2..128 -> n times, **129..255 -> forever** (the decremented value is negative).

#### 3.5 Notes

`noteOn(h, ch, note, vel)` 0x906c (note and vel are the raw bytes; note used as s8, vel as s8):
```
prog = (s8)h.prog[ch]
n = selectTones(h.bank, prog, (s8)note, list)          # spec_play 6.5: tones of that program whose key range holds note
if !lock(): return                                      # always succeeds inside the tick
P = h.bank.programs + prog*8                            # bank +0x20
for i in 0..n-1:
    tone = list[i]
    v = allocVoice(snd.group, (s8)tone.priority)         # snd = h.sound; may steal (callbacks run, 4.0)
    if v == -1: continue
    h.voiceMask[core] |= 1 << ch(v)
    V.owner = h; V.cb = 0x9abc; V.note = note; V.fine = 0; V.tone = tone; V.prio = tone.priority
    V.group = snd.group; V.volR = 0; V.volL = 0
    pan = h.chPan[ch] + h.pan; if pan >= 360: pan -= 360          # once
    vol = trunc((s8)vel * (s8)h.chVol[ch] / 127)
    voiceVolPan(h.vol, vol, pan, P.vol(s8 +1), P.pan(s16 +2), tone.vol, tone.pan, &V.volL)   # spec_play 3.2,
                                                         # master = the handler volume (127 for programs)
    V.ch(+0x2c) = ch; V.pb = h.chBend[ch]; V.vel(+0x2d) = vel; V.pm = h.pm; V.sustained(+0x30) = 0; V.prog(+0x34) = P
    keyOnVoice(v)                                       # spec_play 2.2: registers batched now, KeyOn at this tick's flush
unlock()
```
- One voice per matching tone, in tone order; each voice gets the note itself (fine 0); pitch = `voicePitch(tone,
  chBend[ch], h.pm, note, 0)` via `keyOnVoice`.
- There is no per-handler voice limit and no check for a note already sounding on that channel: a repeated note-on
  takes more voices.
- A program index >= the bank's program count gives no tone (no voice, nothing else).
- The KeyOn goes out at the end of the same tick (`flushKeyOn` follows `handlerTick`).

`noteOff(h, ch, note)` 0x937c:
```
if !lock(): return
for each voice in the active voice list, head first:
    if V.owner == h and V.ch == ch and (s8)V.note == (s8)note:
        if h.sustain >> ch & 1: V.sustained = 1
        else: endVoice(v)          # spec_play 2.3: cb(v, h, 3) if state 1 and cb set (clears h's mask bit), cb = 0,
                                   # pending KON cleared, pending KOFF set -> KeyOff at this tick's flush
unlock()
```
- Every matching voice (all tones of the note, and every earlier note-on of the same note) is released.
- The match uses `owner` only, which is never cleared: voices already released (still linked, in their release) match
  again (another KeyOff, harmless), and so do still-linked voices of an **earlier** handler that used the same slot
  (same address), e.g. the release tail of a stopped sequence when a new sequence took its slot.
- A note-on and its note-off in the same tick: the KeyOn is cancelled (pending bit cleared), a KeyOff is sent.

#### 3.6 Controllers (`0xbn c v`), 0x8ddc

| c | effect |
|---|---|
| 0 (bank select) | `bk = findBankByNumber((s8)v)` (0x43ec: first bank in list 0x14a68, then 0x14a6c, whose **s8 at +0x10** equals v); found: `h.bank = bk`; not found: **stop = 1** (the sequence ends) |
| 7 (volume) | `h.chVol[ch] = v` (stored only: used by later note-ons and by SetSoundParams volume/pan, 4.1) |
| 10 (pan) | `h.chPan[ch] = midiPan((s8)v)` (stored only, same) |
| 64 (sustain) | v >= 64: `h.sustain |= 1<<ch`; else `sustainOff(h, ch)` |
| other | ignored |

`midiPan(p)` 0x82e0: `p < 64: trunc(90*p/64) + 270` (0 -> 270 = full left, 32 -> 315); else `trunc(90*(p-64)/63)`
(64 -> 0 centre, 96 -> 45, 127 -> 90 full right); result s16.

`sustainOff(h, ch)` 0x9470: `h.sustain &= ~(1<<ch)`; lock; for each voice in the active list with `V.owner == h`,
`V.ch == ch`, `V.sustained == 1`: `endVoice(v)` (V.sustained is not cleared); unlock.

#### 3.7 Pitch bend (`0xen lsb msb`), 0x9570

```
raw = (lsb & 0x7f) | (msb & 0x7f) << 7                  # 0..16383
pb = (s16)(divu(raw * 65535, 16383) - 32768)            # 0 -> -32768, 8192 -> +1 (not 0), 16383 -> 32767
h.chBend[ch] = pb
lock()
for each voice in the active voice list, head first, with V.owner == h and V.ch == ch:
    V.pb = pb
    sceSdSetParam(core|ch(v)<<1|0x200, voicePitch(V.tone, pb, V.pm, V.note, V.fine))    # immediately, not batched
unlock()
```
(Applies to released voices of the channel too; the bend range is the tone's +8/+9, spec_play 3.1.)

#### 3.8 How a MIDI sound ends

`seqTick` returns 1 at the end of track with no loop left, at a bank select to an unknown bank, or when the 0x75
sysex language says so; then `handlerTick` calls `stopHandler(h, 0, 0)` (spec_play 5.3): `keyOffMask(h.voiceMask)`
(the voices still held by notes: callback reason 3 clears their bits, KeyOff at this tick's flush) and
`freeHandler(h)` (handle invalid from now on; effect nodes leak as for programs). Effects are not run in that tick.

A MIDI handler is **never** freed by its voices: losing its last voice (stolen, ended, released) does nothing to the
handler. A sequence that loops forever plays until StopSound/StopAllSounds (or a 0x75 sysex stop).

### 4. Voices and the handle commands

#### 4.0 The MIDI voice callback 0x9abc `cb(v, h, reason)`

`h.voiceMask[v/24] &= ~(1 << v%24)`. Nothing else (reason ignored, no stop, no freeing). Calls:
- reason 1, stolen by `allocVoice` (another sound's or this sequence's own later note): the note just goes silent; its
  later note-off finds nothing (owner changed);
- reason 3, `endVoice` from note-off/sustain-off/the tick's 256-silent-tick counter, `keyOffMask`/`silenceMask` from a
  stop;
- reason 2, `freeVoice` (keyed off and ENVX 0): normally the callback is already cleared by then.
So `h.voiceMask` = the voices of notes that are held (not yet released); released voices stay linked with owner h
and no callback until the tick frees them.

#### 4.1 Volume / pan (SetSoundParams mask 1/2, SetSoundVolPan 0x1b, auto-pan steps): `setVolPan` 0x59c4 -> 0x96fc

Under `suspend` (0x59c4). `h = lookup(handle)`; if none: nothing. Then 0x9740:
```
lock()                                     # result ignored; unlock() at the end is unconditional
if vol < 0:                 h.vol = -vol
elif vol != 0x7fffffff:     h.vol = (s16) asr(vol * snd.vol, 10)
if h.vol >= 128: h.vol = 127
if pan == -1: h.pan = snd.pan  elif pan != -2: h.pan = pan
for each voice in the active voice list, head first, with V.owner == h:      # held AND released voices
    pan = h.chPan[V.ch] + h.pan; if pan >= 360: pan -= 360
    vol = trunc(V.vel * (s8)h.chVol[V.ch] / 127)                             # the channel's CURRENT volume/pan
    voiceVolPan(h.vol, vol, pan, V.prog.vol, V.prog.pan, V.tone.vol, V.tone.pan, &V.volL)   # previous L/R in place
    sceSdSetParam(core|ch<<1|0x000, (u16)groupScale(V.volL, V.group) >> 1)
    sceSdSetParam(core|ch<<1|0x100, (u16)groupScale(V.volR, V.group) >> 1)
unlock()
```
(Differences from the program path: walks the voice list instead of the mask, so released voices are updated; group
from the voice; master = h.vol.)

SetSoundParams (0x21) on a MIDI handle (TMB: mask 0x1d every frame on bank 0xe7684 sound 0xb, e.g. vol 0x1d9, pan
0x15f): mask 1 -> 4.1 with pan -2; mask 4 -> auto-pan (spec_play 8: the effect node lives on `h.effects`, its steps
call `setVolPan(handle, 0x7fffffff, np)` = 4.1, run from `handlerTick` after `seqTick` when not paused and not
stopping); mask 8 -> 4.2; mask 0x10 -> pitch bend command 0x5dc4, which **ignores** type 1 (nothing). Result: the
handle if the lookup succeeded at the start, else 0 (spec_play 7.5).

#### 4.2 Pitch modifier (0x20, SetSoundParams mask 8): 0x5e60 -> 0x9970

Under `suspend`. `h = lookup(handle)`; if found, 0x99a8 with `pm = (s16)pm`:
```
lock()
h.pm = pm
for each voice in the active voice list, head first, with V.owner == h:      # every channel, held and released
    V.pm = pm
    sceSdSetParam(core|ch<<1|0x200, voicePitch(V.tone, V.pb, pm, V.note, V.fine))    # immediate
unlock()
```
Later note-ons take `h.pm`.

#### 4.3 Other commands on a MIDI handle

- **StopSound 0x15** (0x586c): `suspend; h = lookup; if h: stopHandler(h, 1, 0); resume` -> KeyOff (next flush) of the
  held voices, handler freed at once; released voices finish their release. Paused: `silenceMask` instead (immediate,
  no KeyOff).
- **StopAllSounds 0x18**: as spec_play 7.2 (MIDI handlers are in the same active list: `stopHandler(h,1,1)`, then
  `silenceMask(all)`).
- **SoundIsStillPlaying 0x19**: `lookup(handle) ? handle : 0`: a MIDI sound plays from its play until its sequence ends
  (3.8) or it is stopped; a loop-forever sequence always answers its handle.
- **PauseSound 0x13** (0x5f9c, types 0, 1, 2, 5): `h.flags |= 2; pauseMask(h.voiceMask)` (VOLL = VOLR = PITCH = 0 for
  the held voices only; released voices keep sounding), recursively for children (+0x28). While paused `handlerTick`
  runs neither `seqTick` nor the effects: the sequence time stops (countdown frozen). **ContinueSound 0x14** (0x6038):
  `resumeMask(h.voiceMask)` (VOLL/VOLR from V.volL/R with group scaling, PITCH from the voice fields), children, then
  flags &= ~2. Group pause/continue 0x16/0x17 (0x6c14/0x6d5c) do the same for every active handler whose group bit is
  in the mask (pause: not already paused; continue: paused). No event is processed while paused; a stop while paused
  silences. A voice that is stolen/ended while paused leaves the mask and is not restored.
- **Pitch bend command 0x1f (0x5dc4)** and **0x1e (0x5d30)**: nothing for type 1. **0x1d (0x5c40)**: types 0 and 5
  only (answers 0 for MIDI).
- **PlaySound result** (0x11): the handle; 0 when the sound has no block / the `MMID` index is out of range / the
  block's bank was not found at load; **0xffffffff** when all 32 MIDI handlers are active.

### 5. Tick order recap for a MIDI sound

Tick (spec_play 4.1): voice loop (ENVX, silent counter, `freeVoice`/`endVoice`) -> `handlerTick` (for each active
handler in list order: `seqTick` for unpaused MIDI handlers, every event due now: note-ons batch registers and set
pending KON, note-offs set pending KOFF; then the handler's effects; stop if asked) -> `flushKeyOff` -> `flushKeyOn`.
So a note-on at delta 0 after a play keys on at the end of the first tick after the play; all events due in a tick
key on/off at that tick's end; a stolen voice gets KOFF then KON in the same flush.

Sequencer timing in driver ticks: with `step` = 100 x MIDI ticks per driver tick, an event is due `count =
ceil(tempo * trunc(x/100) / PPQ / 4170)` ticks after the previous due tick (x = 100*delta + carried remainder), or
in the same tick if x < step/2; `rem = x - step*count`.

### 6. Open questions / not verified

1. The `f0 75` sysex language (0x9f00, 23 opcodes through a jump table at 0x13c30: conditionals on globals such as
   0x15100, per-handler registers, channel mute 0x899c/0x89b4, stopping other handlers via 0x6e9c) is not specified;
   TMB's sequences contain no sysex. Its return value (0 = stop, else a pointer to the byte before the next event) is
   all `seqTick` depends on.
2. Sound type 5 (0x9b10: a type-2 handler that starts every sub-sequence of an `MMID` as a type-3 handler embedded in
   the sub-block at +0x28, sharing `seqTick`) is not covered; no TMB bank has a type-5 sound.
3. `rate` is 4170 (from 240 * 999 / 10, an NTSC-style 0.999 factor), not 4166: settled from the code and the replay's
   global. Any native tick model must use 4170 here even though the timer runs at 240 Hz.
4. The MID header's bank pointer (+0x14) is resolved only at the block's load (by bank id, in the loaded-bank lists);
   whether ResolveBankXREFS (0x08) or an unload re-resolves it was not traced (the loader 0x3678 is the only caller
   found; the unload path 0x37b0/0x3770 walks list 0x14a70). A sequence whose bank is loaded after it would have bank
   0 and every play answer 0. In TMB the MIDI chunk is in the same bank file as its programs.
5. The 0x150f0 guard and the `lock()` failure branch of `noteOn` cannot trigger from the tick (the tick only runs when
   the lock flag is clear and unlock clears it before running missed ticks); kept for completeness.
6. Voices of a stopped MIDI handler that are still releasing keep `owner` = the handler's address; a new MIDI play
   taking the same slot inherits them in note-off/pitch-bend/vol-pan/pitch-modifier matching (3.5). Whether this ever
   happens in TMB's records (shell music slot 0 reused by 0x81000004 at match1p frame 6819, long after) was not
   checked; it needs releases still running when the slot is reused.
7. A 0xa0 (poly pressure) or 0xf1-0xfe status, or an unknown meta type, leaves the pointer on its data bytes, which
   are then read as a delta: deterministic but garbage timing; only the `'CHAM'` sub-sequence 4 case (3.3) occurs in
   TMB's data, and no TMB sound plays that sub-sequence in the traced runs (sounds 5-8 of bank 0xe93f4 use subs 0-3).
8. `ticksFor` on the first tick uses `trunc(100*d/100)` computed with a signed 32-bit multiply: a first delta above
   21,474,836 would wrap. Irrelevant for real data.

#### 1.1 Argument unpacking of 0x2c (0x834)

Request words w0..w6. `playStream(lbnL = w0, lbnR = w1, offL = w2 & 0xffff, offR = w3 & 0xffff, vol = w2 >> 16,
pan = w3 >> 16, group = w4, queueOn = w5, flags = w6)`. vol and pan are unsigned 16-bit (so pan is never -1/-2).

TMB's calls (m1.snd):
- `199303 19a938 4000000 0 1 0 0`: stereo (L at LBN 0x199303, R at 0x19a938), offsets 0, vol 0x400, pan 0, group 1
  (music, `JnkYrdAm(L)/(R)`, 44100 Hz, 11641376 bytes each) -> 0x84000002.
- `19eaf7 1a01eb 0 0 1 0 0`: stereo, vol **0**, pan 0, group 1 (faded in with SetSoundParams) -> 0x84010002.
- `18c5ae 0 4000000 f40000 4 0 0` (three times): mono `DEA_AI_M` (22050 Hz, 52848 data bytes), vol 0x400, pan 0xf4 =
  244, group 4 -> 0x84020002, 0x84020003, 0x84020004.
So the "0x4000000" word is vol 0x400 << 16, not a flag; flags (w6) is always 0 and queueOn (w5) always 0 in TMB.

| 0x1513c / 0x15140 | last sceCdGetError of a stream read / of a safe read (-1 if the read call itself failed with error 0) |
| 0x15144 | thread id sleeping in `safeSync` (0xd7c4), -1 none |
| 0x15148 | safe read destination is EE memory (SIF DMA instead of memcpy) |
| 0x1514c | head of the buffer record list (link at +152) |
| 0x15150 / 0x15154 | **disc queue** head / tail (requests, link at req+12) |
| 0x15158 / 0x1515c | **SPU queue** head / tail (requests, link at req+12) |
| 0x15160 | request whose disc read is in flight (`cdCur`) |
| 0x15164 | 1 while a safe-read chunk is in flight |
| 0x15168 / 0x1516c | request being DMA'd on transfer channel 0 / 1 |
| 0x15170 / 0x15174 | channel 0 / 1 busy (also taken by other code through 0xe590 / released by 0xe628) |

#### 2.2 Stream record (52 bytes, `S = *(0x15110) + slot*52`) — same layout/handle scheme as a program handler

| off | type | meaning |
|---|---|---|
| 0x00 | u32 | handle `bit31 active | 0x04000000 | slot << 16 | gen` |
| 0x04 | ptr | buffer record of the left (or mono) channel `bL`; **0 = record free** |
| 0x08 | ptr | effect chain (auto-pan of SetSoundParams mask 4) |
| 0x0c, 0x10 | s16 | initial copy / current volume (0..127) |
| 0x0e, 0x12 | s16 | initial copy / current pan (degrees) |
| 0x14 | s16 | 0 |
| 0x16 | u8 | flags, bit 1 = paused |
| 0x17 | s8 | volume group |
| 0x18, 0x1c | u32 | voice masks core 0 / core 1 (bit of each stream voice; set at play, never cleared) |
| 0x20 | ptr | next in the active handler list; 0x24/0x28 chain links (0) |
| 0x2c | ptr | `next`: buffer set of the next queued stream, already started (4.4) |
| 0x30 | ptr | play queue (list of 16-byte entries) |

Init (0xb410): `handle = i << 16 | 0x04000001`, +4, +8 = 0, +0x14..0x17 = 0, masks 0, +0x2c = +0x30 = 0.
Allocation 0xfb54 (interrupts off): first slot i (ascending) with `+4 == 0`: `+0x16 = 0`; `handle = 0x04000000 |
i << 16 | ((handle + 1) & 0xffff)`; `+0x20 = +0x24 = +0x28 = 0`; return it (0 if none). So the first play on slot i
returns generation 2 (0x84i0002 after activation), matching the trace (slots 0, 1 = music, slot 2 = DEA_AI_M with
generations 2, 3, 4). Lookup (`lookup` 0x6900, type 4): `rec = table + slot*52`, valid iff `rec.handle == handle`
(no bound check on the slot). The record is freed by `freeHandler` (spec_play 5.2), which zeroes +4 and +8 and
clears bit 31.

#### 2.3 Buffer record (160 bytes, one per stream, allocated at init; `b`)

| off | meaning |
|---|---|
| +0 | flags (below) |
| +4 | `size`: buffer bytes = trunc(bufBytes / 4096) * 4096 (TMB: 0xfa00 -> **0xf000**, half = 0x7800 = 30720 = 15 sectors) |
| +8 .. +35 | request **A** (first half), 28 bytes, see 2.4 |
| +36 .. +63 | request **B** (second half) |
| +64 | current half (0 = A, 1 = B) as last seen by the tick |
| +68 | last NAX seen by the tick |
| +72 | `now` of the last half change |
| +76 | error count |
| +80 / +84 | data reads started / `now` at the last read start (diagnostics) |
| +88 | voice (-1 = none) |
| +96 | next LBN to read; +100 first LBN; +104 byte offset of the VAGp header inside its sector |
| +108 | bytes still to read from the disc |
| +112 | total samples = (dataSize >> 4) * 28 (left buffer only) |
| +116 | bytes played (2.6) |
| +120 | sample rate from the header (-1 until parsed; left buffer only) |
| +124 | last NAX used by the played counter |
| +128 / +132 | volume (0..127) / pan |
| +136 | group |
| +140 | pitch register value |
| +148 | right-channel buffer (left buffer of a stereo stream only; 0 otherwise) |
| +152 | next buffer record (list from 0x1514c) |
| +156 | owning stream record |

Init: `flags = 1`, `size`, req A: iop = b + 160, spu = SPU block of `size` bytes from the module's sound-memory
allocator 0x4d50, owner = b; req B: iop = b + 160 + size/2, spu = spuA + size/2, owner = b; everything else 0.
So each buffer has `size` bytes of sound memory (both halves adjacent) and `size` bytes of IOP memory (one IOP half
per request). TMB: 6 x 0xf000 bytes of sound memory and 6 x (0xf000 + 160) bytes of IOP heap, plus a 0x7800-byte
bounce buffer.

Buffer flags (+0):

| bit | meaning |
|---|---|
| value 1 | free (allocation test `flags & 1`) |
| 0x002 | allocated, voice not started |
| 0x004 | voice set up (KeyOn queued) |
| 0x008 | voice monitored by the stream tick (set by the tick when `flags & 6 == 6`, clearing 0x2) |
| 0x010 | paused (play flag bit 0, PauseVAGStream, queued next buffer) |
| 0x020 | last disc read issued |
| 0x040 | last chunk is in sound memory ("end phase") |
| 0x080 | data ready but no voice yet (queued next buffer, 4.4) |
| 0x100 | reverb on (play flag bit 1) |

#### 2.4 Request (28 bytes inside the buffer: A at b+8, B at b+36)

`+0` flags, `+4` IOP buffer, `+8` SPU address, `+12` queue link, `+16` owner buffer, `+20` last-chunk flag, `+24`
bytes of the chunk.

Request flags:

| bit | meaning |
|---|---|
| 0x01 | initial fill: transfer to sound memory as soon as the disc read completes |
| 0x04 | key the voice on when this transfer completes |
| 0x08 | first data chunk (contains the 48-byte header): do not rewrite ADPCM flags (unless 0x4 also set) |
| 0x10 | header read |
| 0x20 | after this transfer, re-read with flag 0x40 |
| 0x40 | key the voice on when this disc read completes |
| 0x80 | data ready in the IOP buffer |

Queue helpers (all with interrupts off):
- `diskEnqueue(r)` 0xf4e0: if r is already in the disc queue: print, return 0; else append at the tail, r.link = 0,
  return 1.
- `xferEnqueue(r)` 0xf448: if !(r.flags & 0x80): print ("not ready"), return 0; else append to the SPU queue, return 1
  (no duplicate test).
- `diskRemove` 0xf59c / `xferRemove` 0xf644: unlink r from that queue if present.

#### 2.5 `markBlocks(iop, bytes, last)` 0xf310 (ADPCM flag byte = byte 1 of each 16-byte block)

```
if bytes == 16: copy block 0 to block 1; zero block 0; block1.flag = 7; block0.flag = 1; return 32
if bytes == 32: block0.flag = 1; return 32
if !last: block0.flag = 6 (loop start|repeat); block1.flag = 2; blockLast.flag = 3 (end|repeat); return bytes
else:     block0.flag = 4 (loop start); blockLast.flag = 7; blockLast-1.flag = 1 (end, no repeat); return bytes
```
(blockLast = the block at bytes-16.) Flushes the data cache. The return value replaces the request's byte count.

#### 2.6 Played-bytes counter `advance(b, pos)` 0xd18c

```
end = b.spuA + b.size;  if pos > end: pos = end
if pos >= b.last124 (unsigned; false when last124 == 0 and pos == 0... i.e. pos > last124 - 1):
     b.played116 += pos - b.last124
else b.played116 += (end - b.last124) + (pos - b.spuA)        # wrapped round the ring
b.last124 = pos
```
`last124` is set to the start address at KeyOn setup (3.6).

Time queries (all under suspend; 0 for an unknown handle or rate -1): with `p = b.played116`,
`samples = (p >> 4) * 28 + ((p & 15) >= 5 ? ((p & 15) - 4) * 2 : 0)`,
`playedTime = trunc(samples / rate) * 1024 + trunc(((samples % rate) << 10) / rate)` (1/1024 s);
`totalTime` the same with `b.total112`; `remainingTime = totalTime - playedTime`. All unsigned divisions.

### 3. Algorithms

#### 3.1 InitVAGStreamingEx 0xb410 `(n, bufBytes, spindle)`

```
if *(0x1514c) != 0: print; return                    # already initialised
spindle0x1511c = spindle; nStreams = n
size = trunc(bufBytes / 4096) * 4096
create 4 threads (attr 0x02000000, stack 2048, arg 0), priorities from base B = *(0x14904) = 60:
   0xe3ec  "SPU transfer"        prio B+0 = 60
   0xd3a0  "disc reader"         prio B+2 = 62
   0xe7d8  "transfer completion" prio B+1 = 61
   0xdcdc  "CD completion"       prio B+3 = 63
   (in that creation order; ids stored at 0x15190, 0x15194, 0x15198, 0x1519c)
create 4 semaphores {attr 1, init 0, max 1}: semRead, semXfer, semXferDone, semCdDone (0x15180..0x1518c)
zero disc queue, SPU queue, cdCur, channel requests
table = AllocSysMemory(52 * n)            (failure: print, cleanup 0xf8a8, return)
for i in 0..n-1: init record i (2.2)
for i in 0..n-1: allocate a buffer record (2.3), append to the buffer list   (failure: print, cleanup, return)
bounce = AllocSysMemory(size / 2); bounceSectors = (size / 2) >> 11
zero the 64 play-queue entries
StartThread each of the 4 threads (in creation order); initialised = 1
```
IOP priorities: lower number = higher priority, so 60 > 61 > 62 > 63 among the stream threads. In the harness the
command (RPC) thread runs at 58/59, above them: the stream threads only run while the command thread is blocked or
idle (open question 8).

#### 3.2 PlayVAGStreamByLoc 0xbb58

```
          word0 = 1, word3 = 0); fail -> free the taken one, resume, return 0
```

#### 3.3 `allocBuffers(&bL, &bR, stereo, wantVoice, group)` 0xb970

```
bL = first buffer in the list with (flags & 1); if none: return 0
bL.flags = 2; bL.group = group; bL.R = 0
if stereo:
    bR = next free buffer; if none: bL.flags = 1; return 0
    bR.flags = 2; bR.group = group; bL.R = bR
if !wantVoice: bL.voice = -1 (and bR.voice = -1); return 1
v = allocVoice(group, 127)                           # spec_play 2.1: priority 127
bL.voice = v; if v == -1: bL.flags = 1 (bR.flags = 1); return 0
V[v].state = 4                                       # reserved for streaming; NOT linked in the active voice list
if stereo:
    w = allocVoice(group, 127); bR.voice = w
    if w == -1: bL.flags = bR.flags = 1; unlinkVoice(v) (state 0); return 0
    V[w].state = 4

```
So a stream takes **one voice per channel through `allocVoice` with priority 127**: a free voice in range if any
(ascending), else it steals the lowest-priority/oldest program voice (its owner's callback reason 1); it fails only if
the victim has priority 127 (another stream voice or reserved voice). Stream voices (state 4, priority 127, not in the
active voice list) are never stolen and never seen by the tick's voice loop while the stream lives. TMB: group 4 with
split flag 0 -> range 0..47.

#### 3.4 `setupBuffer(s, b, lbn, off, isR)` 0xc148

reqA.last = reqB.last = 0; b.half64 = b.lastNax68 = b.swapTick72 = b.err76 = b.reads80 = b.readTick84 = 0;
b.vol128 = s.vol; b.pan132 = s.pan; b.pitch140 = 0; b.stream156 = s; b.rate120 = -1; b.total112 = 0;

#### 3.5 The disc pipeline (threads)

**Disc reader thread 0xd3a0 (prio 62)** — one disc operation at a time; stream requests before safe (bank) reads:
```
loop:
    if discQ empty or cdCur != 0 or safeActive: WaitSema(semRead)      # (idle or busy -> wait)
    if abort0x15138: finishSafe()                                       # 0xe2f0
    if cdCur != 0 or safeActive: continue
    if discQ not empty:
        r = pop head (interrupts off); cdCur = r
        if r.owner.flags & 0x21: cdCur = 0               # buffer freed (1) or its last read already issued (0x20)
        else startRead(r)                                # 0xdab0
    elif safeSectors0x1512c != 0: safeActive = 1; startSafeChunk()   # 0xd8fc
    if idle (cdCur == 0, !safeActive, discQ empty) and waiter0x1517c: WakeupThread(it); clear
```

**startRead(r)** 0xdab0 (r = cdCur, b = r.owner):
```
if r.flags & 0x10:  sectors = (b.off104 <= 2000) ? 1 : 2              # header read; LBN not advanced
else:
    b.reads80++; b.readTick84 = now
    half = b.size / 2
    if b.toRead108 > half: r.last = 0; bytes = half
    else: b.flags |= 0x20; r.last = 1; bytes = b.toRead108              # last read of the file
    r.bytes = bytes; b.toRead108 -= bytes
    sectors = (bytes + 2047) >> 11
sceCdCallback(cdCallback 0xdcac)
ok = sceCdRead(b.nextLbn96, sectors, r.iop, {trycount 50, spindle, pattern 0})
if !ok: err = sceCdGetError() (0 -> -1); stopStream(b.stream.handle); cdCur = 0; print; report(err)
elif !(r.flags & 0x10): b.nextLbn96 += sectors
```
`cdCallback(reason)`: if reason == 1: iSignalSema(semCdDone).

**CD completion thread 0xdcdc (prio 63)**, after WaitSema(semCdDone):
```
if safeActive: (5.) safe-read chunk completion
else:
    err = sceCdGetError(); if err: print, report
    r = cdCur; if r == 0 or r.owner.flags & 1: cdCur = 0; SignalSema(semRead); continue
    b = r.owner
    if err: stopStream(b.stream.handle); cdCur = 0; continue
    if r.flags & 0x10:                                          # ---- header
        h = r.iop + b.off104
        magic = word h[0]; if magic not 'VAGp' (0x70474156 as a LE word) nor 0x56414770: print; cdCur = 0;
                                                               stopStream; continue
        size = h[12..15], rate = h[16..19]  (byte-swapped when magic is 'VAGp', i.e. the usual big-endian header)
        b.rate120 = rate
        b.pitch140 = (u32)(((u64)(u32)(rate << 12) * 0x057619f1) >> 32) >> 10     # = floor(rate*4096/48000)
                     (22050 -> 1881, 44100 -> 3763, 48000 -> 4095)
        b.total112 = (size >> 4) * 28; b.played116 = 0
        b.reqA.flags = 9; b.reqB.flags = 1
        b.toRead108 = size + b.off104 + 48                      # the first data read re-reads the header sector
        if b.toRead108 < b.size/2 + 1:     b.reqA.flags |= 4    # whole file in half A          (0x0d)
        elif b.toRead108 < b.size + 1:     b.reqB.flags = 5     # whole file in A + B
        else:                              b.reqA.flags |= 0x20 # longer than the buffer      (0x29)
        if stereo (R = b.R148):
            R.toRead108 = size + R.off104 + 48                  # R uses the LEFT header's size, its own offset
            R.pitch140 = b.pitch140; R.reqA.flags = 9; R.reqB.flags = 1; R.played116 = 0
            fail = !diskEnqueue(R.reqA)
        if !fail and b.size/2 < b.toRead108:
            if stereo: fail |= !diskEnqueue(R.reqB)
            if !fail:  fail |= !diskEnqueue(b.reqB)
        if fail: print; stopStream(b.stream.handle); cdCur = 0; continue
        startRead(r)              # r = L's request A, flags now data: the first data read follows at once,
        continue                  # still cdCur (no SignalSema(semRead))
    # ---- data chunk
    if (r.flags & 0xc) != 8: r.bytes = markBlocks(r.iop, r.bytes, r.last)        # 2.5
    r.flags |= 0x80
    if r.flags & 1:          xferEnqueue(r); xfer = 1                             # initial fill
    elif r.flags & 0x40:     keyOnStream(r.owner)                                 # 3.6
    cdCur = 0
    if xfer: SignalSema(semXfer)
    SignalSema(semRead)
```
Notes:
- The very first data chunk of each channel (flags 9, or 0x29 for L) keeps the file's own ADPCM flags (header +
  data as on disc). L's 0x0d (single-half file) is rewritten (flag 4 set). Every other chunk is rewritten by
  `markBlocks`: non-last chunks loop (start 6 / end 3), the last chunk ends with flag 1 on its second-to-last
  block and 7 on its last.
- The right channel never gets 4, 5 or 0x20/0x40: its key-on is done by the left buffer (3.6 handles both voices).

**SPU transfer thread 0xe3ec (prio 60)**:
```
loop:
    if spuQ empty or (ch0req != 0 and ch1req != 0): WaitSema(semXfer)
    for ch in 0, 1:
        if chReq[ch] == 0 and !busy[ch] and spuQ not empty:
            busy[ch] = 1; chReq[ch] = pop head (interrupts off)
            sceSdSetTransIntrHandler(ch, ch == 0 ? 0xe720 : 0xe77c, 0)       # libsd:26
            sceSdVoiceTrans(ch, 0 /*write*/, r.iop, r.spu, r.owner.size / 2)  # libsd:17: ALWAYS a full half
        elif ch == 0: (fall through to ch 1)
    (back to the top)
```
Transfer-end handler (interrupt): `busy[ch] = 0; done[ch] = 1; iSignalSema(semXferDone); if 0x15178 > 0:
iWakeupThread(it), clear; return 0`.

**Transfer completion thread 0xe7d8 (prio 61)**: `if !done0 and !done1: WaitSema(semXferDone)`; if done0:
done0 = 0, `xferDone(0)`; if done1: done1 = 0, `xferDone(1)`; if spuQ not empty: SignalSema(semXfer); loop.

**xferDone(ch)** 0xe88c (r = chReq[ch], b = r.owner):
```
fl = r.flags; r.flags = 0; last = r.last
if b.flags & 1: goto out                                    # stream stopped meanwhile
if fl & 4:              keyOnStream(b)                      # 3.6
elif !(fl & 1):         SetAddr(LSAX of b.voice (0x2140|core|ch<<1), r.spu)   # ring: loop back to this half
if (b.flags & 0x1a) != 0 and !(b.flags & 0x20):             # more to read and buffer alive
    if fl & 0x20: r.flags = 0x40
    if !diskEnqueue(r): stopStream(b.stream.handle)        # next disc read into this request's IOP half
if last: b.flags |= 0x40                                    # end phase: the final chunk is in sound memory
out: SignalSema(semXfer); chReq[ch] = 0; SignalSema(semRead)
```

#### 3.6 `keyOnStream(b)` 0xea88 (b = left/mono buffer)

```

  VOLL  = paused ? 0 : (u16)groupScale(V.volL, V.group) >> 1

   bits are OR-ed into L's two VMIX entries instead of two more entries)
```

The KeyOn goes out at the end of the next tick that runs (`flushKeyOn`, spec_play 4.3).

#### 3.7 The stream tick: `handlerTick` type 4 -> 0xc980 (s)

`handlerTick` calls 0xc980 but **ignores its return value** (type 4 never sets `stop` from it; only the effect chain
can, and the auto-pan callback always returns 0). Then, if the record is still active, not paused and has effects:
`runEffects` (auto-pan, spec_play 8).

```
bL = s.bufL; vL = bL.voice; vR = bL.R ? bL.R.voice : 0; sig = 0

if r == 0:
    if bL.err76 >= 5 or (bL.R and bL.R.err76 >= 5): print; r = -2
    if r == 0 and stereo:                              # stereo consistency checks
        if |bL.played116 - R.played116| > 2048: print; r = -2
        for c in (bL, R): if (c.nextLbn96 - c.firstLbn100 - (c.played116 >> 11)) > (c.size >> 10) + 1: print; r = -2
if r == -1:                                            # ---- normal end
    bL.flags = 1; R.flags = 1 (if stereo)
    if s.queue30: startQueued(s)                       # 4.4
    if s.next2c:                                       # chain into the queued stream (4.4)
        ... (not used by TMB)
    else:
        for each channel voice v (L then R):
            linkVoice(v)          # back into the active voice list, state 1, at the tail
            V[v].prio = 0
            endVoice(v)           # callback (none), pendingKON &= ~bit, pendingKOFF |= bit
        freeHandler(s, 0)         # handle invalid from here on; record free (+4 = 0)
elif r == -2: print; stopStream(s.handle)              # 4.3: same visible result as a normal end
elif sig: SignalSema(semXfer)                          # a refill transfer was queued
startQueued(s)                                         # 0xbfc8, no effect without a queue
```

**`bufTick(b, &sig)` 0xcdd0** — returns 0 (keep), -1 (ended), -2 (error):
```
ret = 0
if (b.flags & 0x18) == 8:                              # monitored and not paused
    v = b.voice
    (interrupts off) a = GetAddr(NAX v); c = GetAddr(NAX v); d = GetAddr(NAX v) (interrupts on)
    pos = (a == c) ? a : (c == d) ? c : (print; re-read three times; same vote; if still none: pos = b.lastNax68)
    if b.spuA <= pos < b.spuB:                  half = 0
    elif b.spuB <= pos < b.spuB + b.size/2:     half = 1
    else:
        b.err76++
        if b.played116 != 0 and b.lastNax68 != 0: return -1        # (no flag update below)
        pos = b.spuA; half = 0
    if b.flags & 0x40:                                  # end phase
        e = GetParam(ENVX v); pos = GetAddr(NAX v)
        if (e & 0xffff) == 0: ret = -1                   # <<< THE END TEST
    else:
        if half != b.half64:                            # the voice entered the other half
            if b.swapTick72 != 0 and now <= b.swapTick72 + 120:
                print ("too fast"); b.err76++
            elif xferEnqueue(request of the half it LEFT = b.half64 ? reqB : reqA):
                sig = 1; b.half64 = half; b.swapTick72 = now
            else: ret = -2                              # data not read yet: the stream is killed
        elif b.lastNax68 != 0 and pos < b.lastNax68:    # went backwards inside one half
            print; ret = -2
        b.lastNax68 = pos
    advance(b, pos)                                    # 2.6
if (b.flags & 6) == 6: b.flags = (b.flags & ~2) | 8    # first tick after keyOnStream: start monitoring next tick
return ret
```
(`now` = the tick counter 0x14ab0.)

### 4. Other stream commands

#### 4.1 PauseVAGStream 0xc250
`suspend; s = lookup(h)`; if s and !(bL.flags & 0x10) and s.flags16 == 0: `s.flags16 |= 2; bL.flags |= 0x10`
(and R); one ProcBatch {VOLL 0, VOLR 0, PITCH 0} for L (and R: 6 entries) — even if the voice is not keyed on yet;
`resume`. A paused stream is not monitored (`(flags & 0x18) != 8`), so it never ends by itself, its voice stays
reserved and its handle stays valid (TMB pauses 0x84000002 at frame 5773 and it answers SoundIsStillPlaying until
the end of the trace). Data already read keeps waiting in IOP memory.

#### 4.2 ContinueVAGStream 0xc468
`suspend; s = lookup(h)`; if s and ((bL.flags & 0x10) or (s.flags16 & 2)): clear s bit 1, clear 0x10 on L and R; if
bL.flags & 4 (voice already set up): ProcBatch {PITCH = pitch140, VOLL = groupScale(V.volL)>>1, VOLR = ...} for L
(and R). `resume`. (If the voice was not set up yet, `keyOnStream` later uses the normal volumes.)

#### 4.3 StopVAGStream 0xc748
```
suspend; s = lookup(h); if !s: resume; return
free the play queue entries (word0 = 0 along the chain)
for b in (bL, bL.R if any):
    b.flags = 1; xferRemove(reqA), xferRemove(reqB), diskRemove(reqA), diskRemove(reqB)
    linkVoice(b.voice); V.prio = 0; endVoice(b.voice)          # KeyOff at this tick's/next tick's flush
if s.next2c: same flag/queue cleanup for it and its R (no voice handling; next2c NOT cleared)
freeHandler(s, 0); SignalSema(semRead); resume
```
A disc read or DMA in flight for a stopped buffer is discarded on completion (`owner.flags & 1`). StopSound (0x15)
and `stopHandler` on a type-4 handle call this. The stopped voices (state 1, priority 0) are freed by the tick voice
loop once keyed off with ENVX 0 (usually the next tick), and are stealable until then.

#### 4.4 Play queue / chaining (not used by TMB; summary)
`startQueued(s)` 0xbfc8: if s.next2c == 0 and s.queue30 != 0: allocBuffers(&nL, &nR, stereo = bL.R != 0,
wantVoice = 0, group = bL.group); nL.flags |= 0x10 (|0x100 if entry flag 2); setupBuffer for each with the entry's
LBN/offset; pop the entry(s); diskEnqueue(nL.reqA); SignalSema(semRead); s.next2c = nL. Its data is read with no
voice: `keyOnStream` only sets 0x80. At the normal end of the current file (3.7, r == -1): `s.bufL = next2c`, the
voices are handed over (next.voice = vL / vR), 0x10 cleared; if next.flags & 0x80: clear it and `keyOnStream(next)`
now; else `continueStream(s.handle)`; s.next2c = 0. The handle stays the same.

#### 4.5 SetSoundParams / volume-pan on a stream handle (0x21 -> `setVolPan` -> 0xfc20)
`SetSoundParams` (spec_play 7.5) works unchanged on type 4: lookup -> result = handle (0 once the stream ended).
mask 1/2 -> `setVolPan(handle, vol, pan)` -> 0xfc20; mask 4 -> auto-pan (spec_play 8, nodes on s+0x08, pan at
s+0x12); masks 8/0x10 (pitch) do nothing for type 4.

0xfc20 `(handle, vol, pan)`:
```
suspend; s = lookup(handle); if !s: resume; return
if vol < 0: s.vol = -vol
elif vol != 0x7fffffff: s.vol = asr(vol * 127, 10)       # scaled by 127 (no sound volume for streams)
if s.vol >= 128: s.vol = 127
if pan == -1: s.pan = 0 elif pan != -2: s.pan = pan
took = lock()
b = s.bufL (0: unlock, resume, print, return)
b.vol128 = s.vol; b.pan132 = s.pan
if b.voice < 48 (unsigned):
    voiceVolPan(127, b.vol, b.pan, 127, stereo ? 270 : 0, 127, 0, &V[v].volL)    # previous L/R kept for the sign rule
    SetParam(VOLL, (u16)groupScale(V.volL, V.group) >> 1); SetParam(VOLR, ...)      # immediate, NOT batched
    stereo: R.vol128/pan132 = same; voiceVolPan(..., progPan 90, &V[w].volL); SetParam VOLL/VOLR of w
if took: unlock()
if s.next2c: copy vol/pan into it (and its R)
resume
```
Remarks: the volume is written even while the stream is paused (unpauses the volume, pitch stays 0), and before the
voice is keyed on (harmless, KeyOn setup rewrites it). TMB's DEA calls: mask 5 every frame (vol 0x400 -> 127, then
auto-pan towards the frame's pan); music fades: mask 1 with vol stepping 8 per frame (fade-in of 0x84010002 from
vol 0) and 0x400 -> 0x3fb... (fade-out of 0x84000002, then paused).

#### 4.6 SoundIsStillPlaying (0x19)
Generic (spec_play 7.3): `lookup(handle) ? handle : 0`. A stream "plays" from PlayVAGStreamByLoc until its record is
freed: normal end (3.7), any `-2` error, StopVAGStream/StopSound/StopAllSounds, or a disc/DMA/queue failure that calls
`stopStream`.

### 5. Bank loads (cmd 0x03) while streaming is initialised: the "safe" read

Bank loading reads the disc through 0x29fc `readBytes(lbn, byteOffset, size, dest)`: a partial first sector via a
1-sector read into 0x17520 + copy, the whole sectors straight to `dest`, a partial last sector via 0x17520 again.
Every disc read is `safeRead(lbn, n, buf)` 0xd55c followed by `safeSync(0)` 0xd7c4 (and before the load,
`safeSync(0)`, `safeSync(16)`).

- `safeRead` 0xd55c: if streaming is not initialised (bounce == 0): plain `sceCdRead(lbn, n, buf, {100, spindle, 0})`.
  Else: if `safeSync(17)` reports busy: return 0 (the load fails); else waiter = -1, dest = buf, nextLbn = lbn,
  sectors = n, toEE = 0; SignalSema(semRead); return 1.
- The disc reader thread serves stream requests first; when none is queued and `sectors != 0` it starts one chunk:
  `chunk = min(sectors, bounceSectors (15 for TMB))`, `sceCdRead(nextLbn, chunk, bounce, {50, spindle, 0})`
  (failure: error report, sectors = 0, wake the waiter).
- The CD completion thread, on a safe chunk: memcpy bounce -> dest (`chunk << 11` bytes; SIF DMA if toEE),
  sectors -= chunk; if any left: nextLbn += chunk, dest += chunk << 11; safeActive = 0; if sectors == 0 (or abort):
  `finishSafe` 0xe2f0 (sectors = 0, wake the waiter with WakeupThread); then if the disc queue or sectors are
  non-empty, SignalSema(semRead).
- `safeSync(mode)` 0xd7c4: not initialised -> sceCdSync(mode). Done (sectors == 0 and !safeActive) -> 0. Mode 1 or
  17 -> 1 (busy, non-blocking). If another thread already waits and mode is 0 or 16: print, return 1. Otherwise
  `while sectors != 0 or safeActive: waiter = GetThreadId(); SleepThread(); waiter = -1`; return 0.

So during streaming a bank load **sleeps the command (RPC) thread** in `safeSync(0)` until its sectors are read
in 15-sector chunks, each chunk waiting behind any queued stream read (stream reads are taken first at every reader
iteration). Meanwhile the tick and the stream threads keep running. The trace's cmd 0x03 returns depend only on the
data, but their completion time (and so the EE time the next commands see) depends on the CD model.

### 6. When a stream ends (the rule for a native driver)

For a stream played and never paused/stopped, with tick period 153600 IOP cycles (240 Hz = exactly **200 output
samples at 48 kHz per tick**):

1. **Start chain** (all in the stream threads, in this order): L header read (1 sector, or 2 if off > 2000) ->
   L chunk A read -> its transfer; then the queued reads (R.A, R.B, L.B in that order for a stereo stream longer
   than half a buffer; L.B only for mono). Reads are sequential (one disc operation at a time); transfers use two
   DMA channels and always move `size/2` bytes.
2. **KeyOn setup** (`keyOnStream`) happens at:
   - file (data + 48 + off) <= size/2: completion of L's chunk A **transfer** (flags 0x0d);
   - <= size: completion of L's chunk B **transfer** (flags 5) — TMB's DEA_AI_M (52896 bytes -> A 30720 + B 22176);
   - longer: completion of the **disc read** of L's 3rd chunk (request A re-read with flag 0x40), i.e. after header,
     A, (R.A, R.B), B, A' reads and the A transfer having re-queued A.
   The voice(s) key on at the `flushKeyOn` of the first tick that runs after that moment (tick T_on). That tick also
   sets flag 8; monitoring starts at T_on + 1.
3. **End test**: from T_on + 1, at each tick, a monitored channel in the end phase (flag 0x40, set when the transfer
   of its **last chunk** completed) reads ENVX; the first tick where ENVX == 0 ends the stream. ENVX drops to 0 when
   the voice finishes the block carrying ADPCM flag 1 (end without repeat: the SPU jumps to LSAX and mutes; ADSR is
   0x000f/0x1fc0, so the envelope otherwise stays at maximum). For a file whose last chunk went through
   `markBlocks` (every case except a one-chunk file), that block is the **second-to-last 16-byte block of the data**;
   VAG data from the disc carry the same flags (TMB: block n-2 = 1, n-1 = 7).
   With SSA = start + off + 48 (data block 0), the voice plays `N = (dataSize/16 - 1) * 28` source samples, i.e.
   `ceil(N * 4096 / pitch)` output samples (pitch = floor(rate * 4096 / 48000)), give or take the SPU's pitch-counter
   phase. So `T_end = T_on + ceil(outputSamples / 200)` (first tick whose ENVX read sees the mute), **independent of
   the disc times once the voice has started**, provided every refill arrived in time (otherwise the stream is
   killed earlier by `xferEnqueue` failing -> -2, same visible end).
   Stereo: the first of L or R to end ends both (L is checked first; R only if L returned 0).
4. **At T_end** (inside `handlerTick`, before flushKeyOff/flushKeyOn): both buffers freed, the voices go back to the
   active voice list (state 1, priority 0) with KeyOff pending (sent at this tick's `flushKeyOff`), and
   `freeHandler(s)`: the handle is invalid for every command after this tick (SoundIsStillPlaying and SetSoundParams
   answer 0). The voices become free at T_end + 1 (voice loop: keyed off, ENVX 0 -> `freeVoice`).

Check against m1.snd (0x84020002, DEA_AI_M, 52848 data bytes = 3303 blocks, 22050 Hz, pitch 1881):
N = 3302 * 28 = 92456, output = ceil(92456 * 4096 / 1881) = 201331 samples -> 1007 ticks after KeyOn. In the replay
(instant CD, cd_delay 0): play at IOP P0; header read at P0+5582 cycles, A (15 sectors) at +5849, A transfer at
+6039, B (11 sectors) at +6364, B transfer at +6630 -> KeyOn at the tick at P0+72839 (1.98 ms); the record is freed
at the tick at P0+154755099 (4198.0 ms) = exactly 1007 ticks later. The trace: alive at +4184.0 ms (frame 8662),
0 at +4200.7 ms (frame 8663); the same for 0x84020003/0x84020004. So the trace is consistent with near-zero CD
latency: the end frame = play time + (start latency to the first tick) + 1007 ticks. With real CD latency (seek +
~30 sectors) the start would be tens of ms later and the end frame would move accordingly; the end therefore
depends on the CD completion times only through T_on.

For long streams (TMB's music) the steady state is: the voice crossing into the other half is seen at the next tick,
which queues the transfer of the half it left (data read one half ahead), and xferDone sets LSAX to that half and
queues the next disc read of 15 sectors. In the replay each refill happens every 53760 source samples (1.2191 s at
pitch 3763), L on channel 0, R on channel 1, followed by the two 15-sector reads.

### 7. Open questions

1. **ENVX after an end-without-repeat block**: the rule assumes the SPU2 behaviour "flag 1 -> jump to LSAX, ENVX = 0
   immediately". The replay's mixer (bzaudio) gives exactly 1007 ticks, matching the trace; real hardware could
   differ by the release phase (ADSR2 release rate 0 = fastest) — at most a tick.
2. The exact output-sample count at which the end flag is seen (pitch-counter phase at KeyOn, the SPU's KeyOn delay of
   a few samples) decides edge cases where `outputSamples` is within a few samples of a multiple of 200.
3. The race in a two-chunk file (mono DEA case): if L's chunk A **transfer** completed before L's chunk B **read**
   started (instant DMA in an emulator), xferDone would re-queue request A (0x20 not yet set) and a 0-byte read
   would follow, whose `markBlocks(iop, 0, 1)` writes before the IOP half (into the buffer record). In the replay the
   B read starts first (the reader thread runs as soon as the A read completes), as on hardware. A native driver
   should simply not re-read.
4. `0xcdd0`'s "-1 when NAX leaves the buffer" path (played != 0 and lastNax != 0) is a second end condition for a
   voice that wandered outside its buffer; not reached by TMB's streams (the end-flag jump lands on LSAX inside
   the buffer).
5. The swap-too-fast check (`now <= swapTick + 120` ticks = 0.5 s) only counts errors; 5 errors kill the stream.
   A half lasts 1.22 s (44.1 kHz) / 2.44 s (22.05 kHz) for TMB's 0x7800-byte halves, so it never triggers.
6. PlayVAGStreamByLoc's `allocStreamRecord` failure path returns without `resume()` (suspend count leaks: the tick
   would stop forever) and leaks buffers/voices. TMB plays at most 3 streams of 6.
7. The play-queue/chaining path (w5 != 0, 4.4) and `0xbfc8`'s return value are only outlined; TMB never uses them.
8. Whether TMB's command thread priority (58/59 in the harness) is the real one: it decides that the stream threads
   never run inside a command (they run in the gaps), so the header read cannot start before the 0x2c command
   returns.
