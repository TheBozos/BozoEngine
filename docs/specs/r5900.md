# Spec: the R5900 instructions BozoEngine translates

What each instruction of the PlayStation 2's Emotion Engine core (the R5900) does, as BozoEngine's recompiler
implements it. Written from the MIPS III/IV architecture and the R5900's own extensions (the 128-bit registers and
multimedia instructions, the second multiply/divide pipeline, the single-precision FPU with its non-IEEE arithmetic,
VU0 in macro mode under COP2). Where we are not sure of the console's exact behaviour the text says what we do and
lists it in section 12 as an open question; the reference records (`reference/tmb/`) are how we settle them.

The code: decoder `recompiler/src/decoder.cpp` (+ `ops.def`), translation `recompiler/src/emitter.cpp`, helpers
`runtime/include/bozo/` (`recomp.h`, `ops_mem.h`, `ops_fpu.h`, `ops_mmi.h`, `ops_vu0.h`). Tests:
`tests/instr/cases.cpp` (each expected value there comes from this document).

## 2. Conventions

- **Registers.** 32 general registers of 128 bits (`ctx->r[n]`, `ud[0]` the low doubleword). Ordinary (MIPS)
  instructions read and write the low 64 bits; the upper 64 bits are changed only by the 128-bit instructions (lq,
  the MMI instructions, qmfc2) and are otherwise **left as they are** (Q16). r0 reads as zero; writes to it are
  dropped (the emitter emits nothing for an instruction whose only effect is writing r0).
- **32-bit results** written to a register are **sign-extended** to 64 bits ("sx32" below). This includes addu/subu,
  the 32-bit shifts, lui, lw, mfc1, mflo/mfhi after a 32-bit multiply (HI and LO hold sign-extended halves).
- **Immediates**: arithmetic and compare immediates are sign-extended (addiu, slti, sltiu, the load/store offset);
  logical immediates (andi, ori, xori) are zero-extended.
- **Addresses** are 32-bit: `base + offset` wraps at 2^32 and uses the low 32 bits of the base register.
- **Delay slots**: the instruction after a branch or jump runs before the branch takes effect; the branch's condition
  and a jump's target register are read before it (section 6).
- **Exceptions** are not modelled except where a runtime call is the point (syscall, break, a trap whose condition
  holds). Integer overflow traps (add, addi, sub, dadd, daddi, dsub) are **ignored**: they behave as addu/addiu/...
  (TMB has 39 of them, all in code where the operands cannot overflow; an overflow would have crashed the console).
  Misaligned lh/lw/ld/sh/sw/sd do not raise an address error; they access the unaligned address (Q21).

## 3. Integer arithmetic and logic

| Instruction | Result |
|---|---|
| addu rd, rs, rt / add | rd = sx32(rs[31:0] + rt[31:0]) |
| subu / sub | rd = sx32(rs[31:0] - rt[31:0]) |
| addiu rt, rs, imm / addi | rt = sx32(rs[31:0] + sext(imm)) |
| daddu / dadd, dsubu / dsub | 64-bit sum / difference |
| daddiu / daddi | rt = rs + sext64(imm) |
| and, or, xor, nor | 64-bit bitwise (nor = ~(rs \| rt)) |
| andi, ori, xori | 64-bit bitwise with the zero-extended immediate |
| lui rt, imm | rt = sx32(imm << 16) |
| slt / slti | 1 if (int64)rs < (int64)rt (or sext(imm)), else 0 |
| sltu / sltiu | 1 if (uint64)rs < (uint64)rt; sltiu compares with the immediate sign-extended to 64 bits then taken as unsigned |
| movz rd, rs, rt / movn | rd = rs if the 64-bit rt is zero / non-zero; otherwise rd unchanged |

Shifts:

| Instruction | Result |
|---|---|
| sll / srl / sra rd, rt, sa | 32-bit shift of rt[31:0] by sa (0-31), logical or arithmetic; rd = sx32(result). `sll rd, rt, 0` sign-extends rt's low word |
| sllv / srlv / srav rd, rt, rs | the same, amount rs[4:0] |
| dsll / dsrl / dsra rd, rt, sa | 64-bit shift by sa |
| dsll32 / dsrl32 / dsra32 | 64-bit shift by sa + 32 |
| dsllv / dsrlv / dsrav | 64-bit shift by rs[5:0] |

## 4. Multiply and divide

HI and LO are 128 bits each on the R5900. The low 64 bits belong to pipeline 0 (mult, div, mfhi, ...), the upper
64 bits to pipeline 1 (mult1, div1, mfhi1, ...); in the context they are `hi`, `lo` and `hi1`, `lo1`.

| Instruction | Effect |
|---|---|
| mult rd, rs, rt | p = (int64)rs[31:0] * (int64)rt[31:0]; LO = sx32(p[31:0]); HI = sx32(p[63:32]); **rd = LO** (the R5900's three-operand form; rd = 0 in the plain MIPS encoding) |
| multu rd, rs, rt | the same with unsigned operands (HI and LO still sign-extended from 32 bits) |
| madd rd, rs, rt / maddu | acc = (HI[31:0] << 32 \| LO[31:0]) + product; LO, HI = sx32 halves of acc; rd = LO |
| div rs, rt | LO = sx32(quotient truncated toward zero), HI = sx32(remainder, sign of the dividend) |
| divu rs, rt | unsigned |
| mult1, multu1, madd1, maddu1, div1, divu1 | the same on HI1/LO1 |
| mfhi / mflo / mthi / mtlo, mfhi1 / mflo1 / mthi1 / mtlo1 | 64-bit moves |

Division edge cases (Q5): by zero, `div` gives LO = -1 when the dividend is >= 0, +1 when negative, HI = the dividend;
`divu` gives LO = 0xFFFFFFFF (sign-extended), HI = the dividend. 0x80000000 / -1 gives LO = 0x80000000, HI = 0. The
console does not trap on division by zero; GCC adds `bnez rt; break 7` checks itself (the 202 `break 7` in TMB).

## 5. Loads and stores

| Instruction | Effect |
|---|---|
| lb / lbu, lh / lhu, lw / lwu | byte, halfword, word; sign- or zero-extended to 64 bits |
| ld / sd | 64 bits |
| lq / sq | 128 bits; the address's **low 4 bits are ignored** (aligned down) |
| sb / sh / sw | the low 8 / 16 / 32 bits |
| lwc1 / swc1 | 32 bits to/from an FPU register (bits moved untouched) |
| lqc2 / sqc2 | 128 bits to/from a VU0 vector register (low 4 address bits ignored; a load into vf00 is dropped) |

Unaligned forms, little-endian (k = address & 3 for the word forms, & 7 for the doubleword forms; "aligned" is the
address with those bits cleared):

| Instruction | Effect |
|---|---|
| lwl rt, a | the word at aligned, shifted left by 8*(3-k), replaces rt's bytes from the top down to byte 3-k; result sign-extended. `lwl rt, off+3(b); lwr rt, off(b)` loads the unaligned word at b+off |
| lwr rt, a | the word shifted right by 8*k replaces rt's low 4-k bytes. k = 0: the whole word, sign-extended; k != 0: the upper 32 bits of rt kept (Q4) |
| swl rt, a | stores rt's top k+1 bytes to aligned..a (rt[31:24] at a) |
| swr rt, a | stores rt's low 4-k bytes from a up to the end of the word |
| ldl / ldr / sdl / sdr | the same on doublewords (k = 0..7) |

The address space recompiled code sees: **guest RAM** 32 MB at 0 (accessed in place, the fast path); everything else
goes through the runtime (`bozo_memory_slow`): the KSEG0/KSEG1 views (0x80000000, 0xA0000000) and the EE's uncached
views (0x20000000, 0x30000000) of RAM, the **scratchpad** (16 KB at 0x70000000), VU0 memory, and hardware registers
(0x10000000-0x1FFFFFFF), which BozoEngine does not model: the runtime answers them as the native libraries need.

## 6. Branches, jumps and calls

All conditional branches compare 64-bit values (beq/bne the whole 64 bits; blez/bgtz/bltz/bgez the signed 64-bit rs)
and jump to `pc + 4 + sext(offset) * 4`. j/jal jump to `(pc + 4)[31:28] | target * 4`.

- **Delay slot**: the next instruction always runs (taken or not), after the condition is evaluated: in
  `beq a0, a1, L; addiu a0, a0, 1` the comparison uses the old a0.
- **Likely** branches (beql, bnel, blezl, bgtzl, bltzl, bgezl, bc0fl/tl, bc1fl/tl, bc2fl/tl): the delay slot runs
  only when the branch is taken; not taken, execution continues at pc + 8 without it.
- **Link**: jal, bltzal, bgezal (and the likely forms) write ra = pc + 8; jalr writes rd = pc + 8 (rd is ra in
  practice). bltzal/bgezal write ra **whether or not** the branch is taken. `bgezal r0` is "bal", a relative call.
- **bc1f / bc1t** branch on FCR31's C bit (section 8); **bc0f / bc0t** on the COP0 condition (CPCOND0, given by the
  runtime); **bc2f / bc2t** on VU0 being busy: VU0 programs finish at once here, so bc2f is always taken and bc2t never.
- A branch in a delay slot is undefined on MIPS; TMB has none, the emitter reports and does not run one.

How the translation maps control flow (abi.md section 3):
- A call (jal, jalr, bal) is a C++ call of the target function, after the link register and the delay slot are
  written; execution continues after the delay slot when it returns. **A function returns** with `jr ra` (and with a
  `jr` through a register that holds a copy of the return address the function was entered with).
- A jump or branch to another function is a tail call (call, then return). A `jr` through a jump table found by the
  analysis is a C++ switch; any other `jr` goes through the runtime's function table.
- A jump into the middle of another function enters that function at the label: such addresses are "extra entries",
  each with its own C++ entry point.
- The scheduler checkpoint (abi.md section 3) runs at every function entry and before every backward branch.

## 8. The FPU (COP1)

32 registers of 32 bits (`ctx->fu[n]`, always handled as bits), FCR31 (`ctx->fcr31`) and the accumulator ACC
(`ctx->facc`). Single precision only. **The arithmetic is not IEEE 754** (helpers: `ops_fpu.h`, all integer code):

- **No infinities, no NaNs.** Exponent 255 is an ordinary exponent: 0x7F800000 is 2^128, 0x7FC00000 is 1.5 * 2^128,
  the largest magnitude is 0x7FFFFFFF (about 6.8e38). A value with exponent 255 is never produced as "Inf/NaN" and
  never treated as one.
- **Denormals are zero.** An operand with exponent 0 is zero of its sign whatever its mantissa; a result smaller
  than the smallest normal becomes zero of its sign (and sets U and SU).
- **Overflow saturates**: a result too large becomes +/-0x7FFFFFFF (sets O and SO).
- **Rounding is toward zero** (truncation).
- **Additions have no guard bits** (Q1): the smaller operand is aligned to the larger one's exponent and the bits
  that fall below the larger operand's last mantissa bit are dropped before the addition; then the sum is
  normalised (a carry out drops one more bit, truncating). Example: 1.0 - 0x3F7FFFFF (1 - 2^-24) gives 2^-23, not
  the exact 2^-24.
- **Zero signs** (Q2): exact cancellation gives +0; -0 + -0 = -0; -0 + +0 = +0; a product or quotient of zeros has the
  xor of the signs.

FCR31 bits: C = 23 (the compare result), I = 17 (invalid), D = 16 (division by zero), O = 15, U = 14, and the sticky
SI = 6, SD = 5, SO = 4, SU = 3. The helpers set the flags an operation raises and never clear them (Q7; TMB never
reads FCR31's flags: no cfc1).

| Instruction | Result |
|---|---|
| add.s fd, fs, ft / sub.s | fs +/- ft, as above |
| mul.s | the exact 48-bit product of the mantissas, truncated to 24 bits (Q10) |
| div.s | the quotient truncated (Q3). ft = 0: D (and SD) set, result +/-0x7FFFFFFF with the sign of fs xor ft; 0/0 sets I (SI) instead, same result |
| sqrt.s fd, ft | the square root of \|ft\|, truncated; ft negative sets I (SI); sqrt(+/-0) = +0 (note: the operand is the **ft** field) |
| rsqrt.s fd, fs, ft | fs / sqrt(ft): the root truncated, then the quotient truncated (Q3). ft = 0: D, +/-max with fs's sign; ft < 0: I, uses \|ft\| |
| abs.s / neg.s / mov.s | clear / flip the sign bit / copy: pure bit operations, no flush, no flags |
| adda.s fs, ft / suba.s / mula.s | ACC = fs + ft / fs - ft / fs * ft |
| madd.s fd, fs, ft / msub.s | fd = ACC + (fs * ft) / ACC - (fs * ft): the product truncated first, then the sum (Q6) |
| madda.s fs, ft / msuba.s | ACC = ACC +/- fs * ft |
| max.s / min.s | the larger / smaller value (sign-magnitude order; zeros of either sign equal) |
| c.eq.s / c.lt.s / c.le.s fs, ft | C = the comparison as values: all zeros (and denormals) equal, otherwise sign-magnitude order (exponent 255 values order normally); c.f.s clears C |
| cvt.w.s fd, fs | truncate toward zero; \|x\| >= 2^31 saturates to 0x7FFFFFFF / 0x80000000; \|x\| < 1 (and denormals) give 0 (Q9) |
| cvt.s.w fd, fs | the 32-bit integer to float, truncated when it needs more than 24 bits (0x7FFFFFFF -> 0x4EFFFFFF) |
| mfc1 rt, fs / mtc1 | bits moved; mfc1 sign-extends |
| cfc1 / ctc1 | FCR31 (register 31); FCR0 reads as an implementation/revision constant (Q18) |
| bc1f / bc1t (+ likely) | branch on C |

## 9. VU0 in macro mode (COP2)

The EE drives VU0's registers directly with COP2 instructions: 32 vector registers vf00-vf31 of four floats
(`ctx->vu0_vf`, x y z w; vf00 is the constant (0, 0, 0, 1) and is never written), the accumulator ACC
(`ctx->vu0_acc`), 16 integer registers vi00-vi15 of 16 bits (`ctx->vi`, vi00 = 0), Q, I, P, R and the flag registers.
The floating-point arithmetic is the FPU's (section 8), field by field (Q1 and Q2 apply the same way; the port's own
VU0 work confirmed "no guard bits" and "-0 + +0 = +0" for VU0 against its interpreter).

Upper (FMAC) instructions: `op.dest fd, fs, ft`, dest a 4-bit field mask (x = bit 24 of the word ... w = bit 21); only
the enabled fields are written. The second operand is a vector (`vadd`), one field of ft broadcast (`vaddbc`: x/y/z/w
in the low two bits of the function field), Q (`vaddq`) or I (`vaddi`).

| Instruction | Effect (on the dest fields) |
|---|---|
| vadd / vsub / vmul (+bc, q, i) | fd = fs op t |
| vmadd / vmsub (+bc, q, i) | fd = ACC + fs * t / ACC - fs * t (product truncated, then the sum) |
| vadda / vsuba / vmula (+bc, q, i) | ACC = fs op t |
| vmadda / vmsuba (+bc, q, i) | ACC = ACC +/- fs * t |
| vmax / vmini (+bc, i) | the larger / smaller value per field |
| vopmula fs, ft | ACC.xyz = (fs.y*ft.z, fs.z*ft.x, fs.x*ft.y) (w untouched) |
| vopmsub fd, fs, ft | fd.xyz = ACC.xyz - (fs.y*ft.z, fs.z*ft.x, fs.x*ft.y): with vopmula, the cross product |
| vabs ft, fs / vmove ft, fs / vmr32 ft, fs | \|fs\| / fs / fs rotated (x <- y, y <- z, z <- w, w <- x), into **ft** |
| vitof0/4/12/15 ft, fs | the 32-bit integers to floats, divided by 2^0/4/12/15 (truncated) |
| vftoi0/4/12/15 ft, fs | floats times 2^n to integers, truncated, saturated to 0x7FFFFFFF / 0x80000000 |
| vclipw.xyz fs, ft | clip flags = (flags << 6 \| judgement) & 0xFFFFFF; judgement bit 0/1: x > +\|ft.w\| / x < -\|ft.w\|, bits 2/3 for y, 4/5 for z |
| vnop | nothing |

Lower instructions available in macro mode:

| Instruction | Effect |
|---|---|
| vdiv Q, fs.fsf, ft.ftf / vsqrt Q, ft.ftf / vrsqrt | Q = fs.fsf / ft.ftf, sqrt(ft.ftf), fs.fsf / sqrt(ft.ftf) (fsf in bits 22-21, ftf in bits 24-23); Q is ready at once (Q12) |
| vwaitq | nothing (Q is ready) |
| viadd id, is, it / visub / viand / vior | 16-bit integer operations on vi (id in bits 10-6) |
| viaddi it, is, imm5 | vi[it] = vi[is] + sext(imm5) (imm5 in bits 10-6) |
| vlqi.dest ft, (is++) / vsqi.dest fs, (it++) | load / store the quadword at VU0 memory address vi*16, then increment the vi (16 bits) |
| vlqd / vsqd | the same with pre-decrement |
| vilwr.f it, (is) / viswr.dest it, (is) | the low 16 bits of one field / the 16-bit integer into the dest fields of the quadword at vi[is]*16 |
| vmtir it, fs.fsf / vmfir.dest ft, is | vi = the field's low 16 bits / each dest field = the vi sign-extended to 32 bits |
| vcallms imm15 | run the VU0 microprogram at byte address imm15 * 8: **a runtime call** (`bozo_vu0_callms`), answered by the port's native version of the program (TMB: `tmb_vu0.cpp`); no VU0 emulation |
| vcallmsr | the same at CMSAR0 * 8 |
| vrnext / vrget / vrinit / vrxor | not translated (not in TMB) |

Register moves:

| Instruction | Effect |
|---|---|
| qmfc2 rt, vf / qmtc2 | all 128 bits between a GPR and a vector register (qmtc2 to vf00 dropped). The .I (interlock) bit is ignored: VU0 is never running a microprogram when the EE looks |
| cfc2 rt, cr / ctc2 | cr 0-15: vi (16 bits, zero-extended); 16 status, 17 MAC, 18 clip, 20 R, 21 I, 22 Q, 27 CMSAR0: in the context; others (28 FBRST, 29 VPU-STAT, 31 CMSAR1...) go to the runtime |

VU0's MAC and status flags are **not computed** by macro instructions (Q11): TMB never reads control registers 16-18
(no cfc2 on them) and its microprograms are native. VU0 data memory is 4 KB; vi addresses wrap at 256 quadwords (Q13).

## 10. MMI: the 128-bit multimedia instructions

Lanes: b = 16 bytes, h = 8 halfwords, w = 4 words, d = 2 doublewords; lane 0 is the least significant. Results are
128 bits (rd's upper half included). "s" is rs, "t" is rt.

| Instruction | Effect |
|---|---|
| paddw/h/b, psubw/h/b | lane-wise wrap-around add / subtract |
| paddsw/h/b, psubsw/h/b | signed saturating |
| padduw/h/b, psubuw/h/b | unsigned saturating |
| padsbh | halfwords 0-3: s - t; 4-7: s + t |
| pcgtw/h/b, pceqw/h/b | lane = all ones if s > t (signed) / s == t, else 0 |
| pmaxw/h, pminw/h | signed max / min |
| pabsw/h | absolute value of t; the most negative value saturates to the most positive (Q8) |
| pand, por, pxor, pnor | 128-bit bitwise |
| psllh/psrlh/psrah rd, rt, sa | per halfword, by sa & 15 |
| psllw/psrlw/psraw | per word, by sa & 31 |
| psllvw/psrlvw/psravw rd, rt, rs | words 0 and 2 of rt shifted by rs's words 0 and 2 (& 31); each result sign-extended to a doubleword |
| pextlw rd, rs, rt | {t.w0, s.w0, t.w1, s.w1} (interleave the low halves; t in the even lanes) |
| pextuw | the same with the upper halves |
| pextlh/pextuh, pextlb/pextub | the same per halfword / byte |
| ppacw rd, rs, rt | {t.w0, t.w2, s.w0, s.w2} |
| ppach, ppacb | the even halfwords / bytes of t, then of s |
| pext5 / ppac5 | 1-5-5-5 colours to 8-8-8-8 (each 5-bit field at the top of its byte, the alpha bit at bit 31) and back |
| pcpyld rd, rs, rt | {t.d0, s.d0} |
| pcpyud rd, rs, rt | {s.d1, t.d1} |
| pcpyh rd, rt | halfword 0 of each doubleword copied to its four halfwords |
| pinth rd, rs, rt | {t.h0, s.h4, t.h1, s.h5, t.h2, s.h6, t.h3, s.h7} |
| pinteh | {t.h0, s.h0, t.h2, s.h2, ...} (the even halfwords interleaved) |
| pexeh / pexch, prevh | swap halfwords 0 and 2 / 1 and 2 of each doubleword; reverse its four halfwords |
| pexew / pexcw | swap words 0 and 2 / 1 and 2 |
| prot3w | {t.w1, t.w2, t.w0, t.w3} |
| plzcw rd, rs | for words 0 and 1 of rs: the number of leading bits equal to the sign bit, minus 1 (rd's upper half kept) |
| pmfhi / pmflo rd | rd = {HI, HI1} / {LO, LO1} |
| pmthi / pmtlo rs | HI = rs.d0, HI1 = rs.d1 (LO likewise) |
| qfsrv rd, rs, rt | the 256-bit value rs:rt (rs high) shifted right by SA bits; the low 128 bits |

**SA, the shift amount register**: `mtsab rs, imm` sets SA = ((rs ^ imm) & 15) * 8 (a byte shift); `mtsah rs, imm`
sets SA = ((rs ^ imm) & 7) * 16 (a halfword shift); `mtsa rs` / `mfsa rd` move it (we hold it in bits: Q14). With
`lq` of two aligned quadwords and `mtsab addr, 0`, `qfsrv` gives the unaligned quadword at addr (TMB's use).

Decoded but **not translated** in milestone 1 (none appears in TMB; they emit a `bozo_unimplemented` call): the
MMI multiply/divide family (pmaddw, pmsubw, pmultw, pdivw, pmadduw, pmultuw, pdivuw, pmaddh, phmadh, pmsubh, phmsbh,
pmulth, pdivbw), pmfhl.*, pmthl.lw; the TLB instructions; vrnext/vrget/vrinit/vrxor.

## 11. Encodings

The decoder's tables (`decoder.cpp`) are the reference. Primary opcode 28 is MMI (function 8/40/9/41 select MMI0-3 by
the sa field; 48/49 are pmfhl/pmthl), 30/31 lq/sq, 54/62 lqc2/sqc2. COP1 fmt 16 is .S, fmt 20 .W (cvt.s.w only).
COP2 with bit 25 set is a VU0 macro instruction: function 0-59 its first table; 60-63 its second table, indexed by
bits 10-6 times 4 plus the function's low two bits.

## 12. Open questions

Each is a place where we chose a behaviour without being sure it is the console's. The milestone-2 comparison
against the reference records (whole functions run under both, registers and memory compared) is how they get
settled; a test in `tests/instr/cases.cpp` pins the current choice (named with the question's number).

- **Q1. Addition without guard bits.** The EE's FPU adder (and VU0's) is said to drop the smaller operand's bits
  below the larger one's last mantissa bit before adding. We do that for add/sub/madd/msub and VU0. Confirmed only
  for VU0, by the TMB port against an interpreter, not on hardware; not confirmed for the FPU. Related: after a
  cancellation (normalising left), are zeros shifted in (our choice) or one retained bit?
- **Q2. Signs of zero.** Exact cancellation = +0, -0 + -0 = -0, -0 + +0 = +0 (as IEEE round-toward-zero). The port's
  VU0 notes agree ("ADDbc vf0 turning -0 into +0"); the FPU is unconfirmed.
- **Q3. Division and roots.** div.s and sqrt.s truncate the exact result (some sources say the divider rounds to
  nearest). 0/0: we give +/-0x7FFFFFFF with I; sqrt of a negative: sqrt(\|x\|) with I. rsqrt.s: one rounding or two
  (we truncate the root, then the quotient)?
- **Q4. lwr's upper bits.** With k != 0 (the word's top byte not loaded) we keep rt's upper 32 bits; with k = 0 we
  sign-extend. MIPS III leaves it to the implementation; the R5900 manual's wording should be checked.
- **Q5. Division by zero and overflow** results of div/divu/div1/divu1 (section 4): from memory of the console's
  observed behaviour, not from a document.
- **Q6. madd.s/msub.s (and VU0 vmadd...)**: product truncated to single precision before the addition (our choice), or
  kept wider? Does an overflow of the product saturate before the sum?
- **Q7. FCR31 flags.** Are O/U/D/I cleared by each operation (and only the sticky ones accumulate)? Do abs/neg/mov
  touch the flags? Irrelevant to TMB (no cfc1), needed for a game that reads them.
- **Q8. pabsw/pabsh** of 0x80000000 / 0x8000: saturate (our choice) or stay negative?
- **Q9. cvt.w.s** boundaries: values in [2^31, 2^32) and exponent-255 values saturate (our choice); is negative
  saturation exactly 0x80000000? cvt.s.w truncates (no rounding mode on the EE)?
- **Q10. mul.s exactness.** We truncate the exact product. The EE's multiplier is reported to differ from that by 1 ulp
  for some operands (partial products truncated). Needs hardware-derived data (or the reference records).
- **Q11. VU0 flags in macro mode** (MAC, status, sticky, clip from vclip) are not computed except clip by vclipw. A
  microprogram (run natively) that reads flags left by macro code would need them.
- **Q12. Q timing.** vdiv's result is used at once here. On the console a macro-mode instruction reading Q waits for
  the divider (or reads the old Q without vwaitq?). TMB: one vdiv, followed by vmaddq.
- **Q13. VU0 memory addressing** in macro mode: we wrap vi*16 at 4 KB. Do addresses above 0x400 quadwords reach VU1's
  registers as in micro mode?
- **Q14. SA's unit.** mfsa after mtsab: is SA held in bytes, bits or another unit? Matters only for code that saves and
  restores SA (thread switches); TMB has no mfsa/mtsa.
- **Q15. COP0**: what CPCOND0 (bc0f/bc0t) means for the runtime (DMA completion), and what TMB reads in COP0 register
  28 (4 mfc0, next to its `cache` instructions) — the runtime's to answer.
- **Q16. Upper 64 bits** of a GPR after an ordinary 64-bit instruction (ld, daddu, mfhi, mfc1...): kept (our choice).
  The R5900 manual should say whether any of them clear or extend into the upper half.
- **Q17. C++ exceptions.** `__throw`, `__rethrow` and `__sjthrow` (libgcc's exception code linked into TMB) jump
  through registers to handlers in other functions with the stack unwound; the call/return model cannot express that.
  If TMB ever throws (to check in the reference traces), those need a runtime mechanism (longjmp-style).
- **Q18. FCR0** (cfc1 from register 0): we return 0x2E30; the true implementation/revision value is unchecked.
- **Q19. Overflow traps** of add/addi/sub/dadd/daddi/dsub are ignored. If a game relies on catching one, that game
  needs it.
- **Q20. Branches in delay slots**: none in TMB; not supported.
- **Q21. Misaligned access exceptions** are not modelled (the access just happens unaligned).
- **Q22. max.s/min.s with zeros of both signs**: we return the first operand when they compare equal.

## 13. What the analysis finds in TMB

For the record of milestone 1 (`bozo-recomp SCUS_971.01 <dir> --verbose`): 3,609 functions (3,568 from ELF function
symbols, 41 carved from code no symbol covers: C++ this-adjusting thunks reached through vtables, hand-written
assembly such as `sysSetSp`), 149 extra entry points (branches between functions, code pointers into the middle of a
function), 114 jump tables (2,684 entries), 1 return through a copy of ra (`texmActivateTextureAsm`), 4 `jr` through
a register the analysis cannot resolve (one in `texmActivateTextureAsm`, the libgcc exception code of Q17), no branch
in a delay slot.
